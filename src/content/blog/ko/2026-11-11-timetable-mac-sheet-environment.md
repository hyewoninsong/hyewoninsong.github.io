맥에서도 시간표를 편집할 수 있게 아이패드 앱을 Mac Catalyst 로 빌드하고 있다. 이번에는 메뉴바, 시트, 창 크기를 하나씩 눌러 봤다. 그러다 시간표 목록이 Mac 에서만 열리지 않는 걸 찾았고, 쓸모없는 메뉴 항목과 설정 몇 개도 같이 정리했다.

## 시간표 목록이 안 열린 게 아니라, 앱이 죽고 있었다

메뉴바에서 보기 › 시간표 목록을 누르면 화면에 아무 변화가 없었다. 처음에는 메뉴 항목이 어디에도 연결되지 않은 줄 알았다. 그래서 목록 상태를 켜는 함수와 시트 내용의 `body` 에 로그를 달았다. 상태는 `true` 로 바뀌었는데 시트 내용의 `body` 는 한 번도 불리지 않았다.

내용을 `Text` 한 줄로 바꾸자 시트가 떴다. 목록 시트 자체가 문제라는 뜻이었다. 그런데 메인 스레드를 샘플링하려 하니 프로세스가 없었다. 진단 리포트 폴더에는 버튼을 누를 때마다 크래시 기록이 하나씩 쌓여 있었다.

```
_assertionFailure
EnvironmentValues.subscript.getter
EnvironmentBox.update(property:phase:)
```

목록 시트는 창마다 하나씩 있는 `@Observable` 상태 객체를 `@Environment(SceneState.self)` 로 읽는다. 아이패드에서는 시트가 이 값을 띄운 쪽에서 물려받는다. Mac 에서는 그 값이 없어서 읽는 순간 어서션이 걸렸다. 앱은 죽었다가 곧바로 다시 떴고, 그래서 겉으로는 "눌렀는데 아무 일 없음"으로 보였다.

같은 날 오전에는 편집 팝오버가 `@EnvironmentObject` 를 못 받아 죽는 문제를 고쳤다. 그때 고친 범위는 팝오버뿐이었다. 시트도 같은 일을 겪는지는 열어 보지 않았다.

## 고친 방법: 띄우는 쪽이 공유 객체를 직접 넘긴다

팝오버에 쓰던 래퍼를 시트에도 쓸 수 있게 넓혔다. 띄우는 쪽에서 루트의 공유 객체 열 개를 읽어 두고, 시트 내용에 `.environmentObject` 와 `.environment` 로 다시 넣는다. Mac 빌드에서만 그렇게 하고, iOS 에서는 원래의 `.sheet` 를 그대로 쓴다.

앱의 시트를 전부 바꾸지는 않았다. 설정, 시간표 설정, 이미지 내보내기, 인쇄 시트는 같은 조작에서 멀쩡했다. 이 시트들은 창 단위 객체를 읽지 않는다. 그래서 규칙을 이렇게 정했다. 새 팝오버는 항상 래퍼로 띄우고, 시트는 창 단위 객체를 읽을 때만 래퍼로 띄운다.

## 맥에서 쓸모없는 것들을 정리했다

- **파일 메뉴**: 앱이 `.supertimetable` 파일 형식을 선언하고 있어서, Mac 이 문서 앱용 항목을 파일 메뉴에 끼워 넣었다. 열기, 최근 사용 열기, 복제, 이동, 이름 변경, 다음으로 내보내기다. 이 앱은 문서 앱이 아니라서 전부 꺼진 채로 남아 있었다. SwiftUI 의 `CommandGroup(replacing: .saveItem)` 로는 빠지지 않아서, 앱 델리게이트의 `buildMenu` 에서 `.open` 과 `.document` 메뉴를 뺐다.
- **사운드·햅틱 카드**: 이 앱에서 소리가 나는 곳은 알람음 미리듣기뿐이다. 그런데 Mac 판에는 알람이 없고, `UIFeedbackGenerator` 는 Mac 에서 진동하지 않는다. 눌러도 아무것도 바뀌지 않는 스위치 두 개여서 Mac 에서는 카드째 숨겼다. 저장된 값은 그대로 둔다.

![Mac 판 설정 시트. 화면·백업 카드만 있고 사운드 및 햅틱 카드는 없다](/blog/timetable-mac-sheet-environment/settings-no-haptics.png)

창을 가장 작게 줄이는 것도 확인했다. 480 × 560 아래로는 줄어들지 않았고, 그 폭에서는 아이폰과 같은 화면 구성(하단 툴바)으로 바뀌었다. 창보다 큰 시트를 띄우면 Mac 이 창을 시트 크기에 맞게 키운다.

## 화면이 잠긴 Mac 에서 확인하는 법

작업하는 동안 Mac 화면이 계속 잠겨 있었다. `screencapture` 는 검은 화면만 찍었고, 손쉬운 사용 API 로 앱 창을 찾으면 0개가 나왔다. 그런데 메뉴바 항목은 잠긴 상태에서도 `System Events` 로 읽고 누를 수 있었다. 메뉴를 하나씩 덤프해서 파일 메뉴 구성을 확인했고, 시트도 메뉴로 열었다.

화면은 앱이 스스로 찍게 했다. 디버그 빌드에만 넣은 임시 코드가 타이머로 창을 `drawHierarchy` 로 그려서 앱 컨테이너에 저장한다. 시트처럼 위에 띄운 화면은 창 그림에 들어가지 않아서, `presentedViewController.view` 를 따로 그려야 했다. `layer.render` 를 쓰면 SwiftUI 화면이 하얗게 나왔다.

## 남은 것

위젯이 Mac 위젯 갤러리에 실제로 보이는지와 툴바의 `…` 메뉴는 잠긴 화면에서 누를 방법이 없어서 아직 못 봤다. 위젯 익스텐션이 시스템에 등록되어 있는 것과, 앱이 앱 그룹에 시간표 데이터를 쓰는 것까지는 확인했다. 그리고 Mac 에서 "눌러도 아무 반응이 없다"는 증상을 보면 이제 진단 리포트부터 연다.
