목록에서 시간표를 고르면 이제 그리드가 처음부터 제자리에 그려진다. 전에는 좌상단에 조금 뭉쳐 있다가 0.2초쯤 커지면서 자리를 잡았고, 의도한 연출이 아니라 버그로 보였다.

## 뭉쳐 있다가 펴지는 0.2초

![시간표를 고른 직후 세 프레임. 시각 눈금이 두 벌로 겹치고 새 그리드의 칸이 좁게 그려졌다가 넓어진다](/blog/2026-10-05-timetable-grid-entrance-first-load/entrance-before.png)

고치기 전의 탭 직후 세 프레임이다. 사라지는 시간표와 나타나는 시간표가 잠깐 겹치는 건 의도한 크로스페이드인데, 새 그리드가 **다른 크기로** 겹친다. 시각 눈금이 두 벌이고 칸 폭이 좁다. 새 그리드 블록의 오른쪽 끝을 프레임마다 재면 318 → 327 → 333 → 337 → 339 → 341pt 로 수렴한다. 위 끝도 201 → 225pt 로 내려온다.

![고친 뒤 같은 구간. 새 그리드가 첫 프레임부터 최종 위치에 있고 불투명도만 올라간다](/blog/2026-10-05-timetable-grid-entrance-first-load/entrance-after.png)

고친 뒤에는 처음 잡힌 프레임부터 341 / 225 이고 그 뒤 60프레임이 같다. 남은 건 페이드뿐이다.

## 스프링은 "처음 채우기"와 "바꾸기"를 구별하지 못한다

하루 전에 표시 범위(시작·종료 시각, 요일 수)를 바꾸면 그리드가 툭 점프하던 걸 스프링으로 바꿨다. 범위를 묶은 키 하나에 `.animation(_:value:)` 를 건 것이다.

문제는 그리드가 범위를 `@State` 로 들고 있다는 점이다. 뷰는 기본값(9–18시, 기본 요일)으로 한 번 그려지고, 바로 다음 갱신에서 `.task` 가 저장된 실제 값을 넣는다. `.animation(_:value:)` 입장에서는 이것도 키가 바뀐 것이다. 사용자가 범위를 바꾼 것과 구별할 방법이 없으니 똑같이 스프링을 붙인다. 요일 수가 기본값과 다르면 칸 폭이, 시작 시각이 다르면 세로 위치가 보간된다.

처방은 첫 로드만 암묵 애니메이션을 끄는 것이다.

```swift
var transaction = Transaction()
transaction.disablesAnimations = true
withTransaction(transaction) { loadTimetableSettings() }
```

나중에 오는 로드(언두, 다른 창에서의 변경)는 그대로 둔다. 그건 진짜 변경이라 스프링을 타야 한다.

검토한 다른 길은 둘이다. "로드가 끝났다" 는 플래그로 `.animation` 을 켜는 방법은, 플래그와 값이 같은 갱신에서 바뀌면 그 갱신이 이미 애니메이션 대상이라 플래그를 한 박자 늦춰야 한다. 타이밍에 기대는 코드가 된다. 초기값을 `init` 에서 모델로 채우는 방법은 저장소가 환경 객체라 `init` 에서 읽을 수 없었다.

## 범인을 한 번 잘못 짚었다

같은 날 시간표 전환 크로스페이드도 들어갔다. 증상이 "전환할 때 이상하다" 였으니 그쪽을 먼저 의심했고, 새 그리드로 내려가는 애니메이션을 끊는 수정을 넣었다. 녹화를 작은 타일로 뽑아 보니 고쳐진 것처럼 보여서 PR 까지 올렸다.

블로그에 쓸 그림을 원본 해상도로 다시 뽑다가 눈금이 여전히 두 벌인 걸 봤다. 고쳐지지 않았던 것이다. 90픽셀짜리 타일에서는 안 보이는 차이였다.

그래서 변형 넷을 한 빌드에 넣고 한 번에 녹화했다. 원본, 크로스페이드 끔, 애니메이션 무조건 차단, 조건부 차단. 크로스페이드를 끈 변형에서도 그리드는 똑같이 커지며 나타났다. 바깥에서 애니메이션을 끊는 변형도 소용없었다. 스프링은 위에서 내려오는 게 아니라 그리드 안의 `.animation(value:)` 가 그 자리에서 붙이기 때문이다.

두 가지를 절차로 남겼다. 전환 판정은 타일을 눈으로 보지 않고 프레임별 좌표를 나열해서 한다. 수열이 수렴하면 애니메이션이고 한 줄이면 통과다. 그리고 의심 가는 변경이 둘이면 하나씩 끈 변형을 같은 빌드에서 비교한다.

## 남은 것

아이패드 레이아웃은 같은 그리드 코드를 쓰지만 따로 재지는 않았다. 값에 애니메이션을 걸 때는 그 값이 처음 채워지는 경로가 있는지부터 센다.
