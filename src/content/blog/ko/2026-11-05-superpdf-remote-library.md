SuperPDF 의 책은 지금까지 파일 앱에서 고른 PDF 로만 만들 수 있었다. 이제 집의 NAS 에 WebDAV 나 SMB 로 붙어 폴더를 훑고, 여러 권을 한 번에 책장에 꽂는다. 꽂는 순간에는 PDF 를 받지 않는다. 카드만 생기고, 처음 열 때 받는다.

## 가져오기는 카드를 만들고, 열기가 파일을 받는다

설정의 "서버" 에 주소·공유 이름·계정을 넣고 "연결 확인" 을 누르면 폴더 수로 답이 온다. 비밀번호는 키체인에 들어가고 설정 파일에는 남지 않는다. 홈의 `+` 는 이제 "파일에서" 와 "서버에서" 로 갈린다. 서버 쪽은 폴더를 내려가며 PDF 만 보여 주고, 이미 책장에 있는 파일은 "이미 있어요" 로 흐리게 나온다.

![서버 폴더에서 PDF 를 고르는 화면. 아래에 "지금 내려받기" 와 "용량 줄여 가져오기" 토글이 있고, 기본값은 둘 다 꺼져 있다.](/blog/superpdf-remote-library/browser-select.png)

아래 토글 둘이 이 기능의 성격을 정한다. "지금 내려받기" 는 기본이 꺼져 있다. 그래서 스무 권을 골라도 기기에는 카드 스무 장만 생기고, 쪽수 자리에는 "내려받지 않음" 과 구름 배지가 붙는다. 책을 열면 문서 자리에 진행 막대가 뜨고, 다 받으면 그대로 읽기로 이어진다.

![책을 열자 문서 자리에 구름 아이콘과 "서버에서 책을 받고 있어요", 진행 막대, 취소 버튼이 보인다.](/blog/superpdf-remote-library/fetch-on-open.png)

"용량 줄여 가져오기" 는 받은 직후 스캔 쪽을 JPEG 로 바꾸고 글자 인식 결과를 보이지 않는 글자 층으로 깐다. 지난주에 만든 "용량 줄인 PDF" 를 가져오기 시점으로 당긴 것이고, 같은 설정이 파일 앱에서 가져올 때도 먹는다.

## 스트리밍이 아니라 캐시인 이유

처음 요구는 "로컬에 안 받고도 읽고 필기할 수 있나" 였다. 답은 "순수 스트리밍은 아니다" 였다.

- **바이트 범위 스트리밍** — PDFKit 의 `PDFDocument` 는 로컬 파일이나 통째 `Data` 로만 열린다. 필요한 범위만 원격에서 읽어 오는 공개 경로가 없다. 거기에 이 앱은 쪽 미리 그리기, 글자 인식, 검색, 소리 내어 읽기, 목차 만들기, 중복 책 찾기가 전부 파일을 직접 연다. 그 열 곳을 모두 원격 대응으로 바꾸는 건 몇 주짜리 공사이고 결과도 느리다.
- **가져올 때 전부 받기** — 구현은 제일 쉽지만 기기 용량을 아끼려는 기능의 반대다.
- **열 때 받아 캐시에 두기** — 고른 쪽. 필기는 원래 PDF 밖, 앱 데이터베이스에 있으니 PDF 파일이 사라져도 잃는 게 없다. 그래서 받은 파일을 `Caches` 에 두어도 된다. 시스템이 공간이 모자랄 때 비워도 되고, 백업에 실려 나가지도 않는다. 서버에 원본이 있는 파일을 백업할 이유가 없다.

Caches 는 어느 날 비워질 수 있다. 그때는 다시 받는다. 밑줄과 읽던 쪽은 모델에 있다. 꼭 들고 다니고 싶은 책만 카드 메뉴의 "이 기기에 보관" 으로 Documents 에 옮긴다.

## 스키마를 올리지 않았다

서버 출처(어느 서버의 어느 경로)는 SwiftData 에 넣지 않았다. 책갈피와 만든 목차가 이미 쓰는 방식대로 PDF 파일마다 JSON 사이드카 하나다. 스키마 V8 로 마이그레이션을 걸어서 얻는 게 없었다. 책마다 독립이고 CloudKit 도 안 쓴다. 읽는 코드는 `PDFFile.fileURL` 한 곳만 바꿨다. Documents 에 파일이 있으면 그것, 없는데 출처가 있으면 Caches 자리. 썸네일·OCR·내보내기·열기가 이 한 줄을 따라온다.

서버 파일이 바뀐 것은 크기로 안다. 받은 바이트 수가 가져올 때 본 크기와 다르면 "서버의 PDF 가 바뀌었어요. 밑줄 위치를 확인해 주세요" 토스트가 뜬다. ETag 와 수정 시각은 SMB 와 WebDAV 구현마다 달라 크기보다 믿을 수 없었다. 크기가 같은 변경은 놓친다는 한계는 안다.

## 프로토콜 둘, 그리고 LGPL

WebDAV 는 그냥 HTTP 라 `URLSession` 으로 직접 썼다. `PROPFIND` 한 번에 폴더 목록이 오고 `GET` 으로 받는다. SMB 는 시스템 API 가 없어 AMSMB2 를 SPM 으로 넣었다. 래퍼는 MIT 이지만 안의 libsmb2 가 LGPL-2.1 이다. 이 패키지가 **동적 라이브러리**로 빌드되는 덕에 재링크 요건을 지키며 앱스토어에 낼 수 있다. 정적으로 바꾸면 그 보장이 사라지므로 제품 형태는 건드리지 않는다. FTP 는 뺐다. 평문이고 요즘 NAS 에서는 꺼 두는 쪽이 기본이다.

리뷰에서 하나 잡혔다. SMB 다운로드의 진행 콜백이 `!Task.isCancelled` 를 돌려줘 "취소되면 멈춘다" 고 믿고 있었는데, 그 콜백은 라이브러리의 자기 큐에서 돈다. 어느 Swift Task 안도 아니라서 `Task.isCancelled` 는 언제나 false 다. 취소 버튼을 눌러도 파일이 끝까지 내려올 코드였다. `withTaskCancellationHandler` 로 락 보호 플래그를 뒤집고 콜백이 그 플래그를 읽도록 고쳤다. `URLSession.download(for:)` 처럼 async 를 직접 주는 쪽은 취소를 알아서 전파해서 WebDAV 는 멀쩡했고, 그래서 더 헷갈렸다.

## 남은 것

실제 NAS 에 붙여 본 건 아직 없다. WebDAV 는 가짜 서버로, SMB 는 경로 조립과 오류 변환만 검사했다. Digest·NTLM 인증, 자체 서명 인증서, 로컬 네트워크 권한 창, 큰 파일의 진행과 취소가 실기 확인 목록이다. 오픈소스 고지 화면도 배포 전에 들어가야 한다. 같은 날 필기를 파일 하나로 내보내는 `.superbook` 도 들어갔는데, 그 형식 이야기는 따로 적는다.
