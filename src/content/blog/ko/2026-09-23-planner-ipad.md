플래너가 아이패드에서도 그대로 쓰인다. 세로로 세우면 하루가 길게 펼쳐지고, 가로로 눕히면 블록이 넓어지고, 화면을 반으로 갈라 다른 앱과 나란히 두면 아이폰과 같은 모양으로 좁아진다. 창을 둘 열면 각자 다른 날을 볼 수 있다. 이걸 위해 아이패드 전용 화면을 하나도 만들지 않았다는 것이 이 글의 요점이다.

## 먼저 잰 것 — 이미 거의 돌아가고 있었다

아이패드 작업은 "아이패드에서 뭐가 깨지나" 를 찍는 데서 시작했다. 아이패드 시뮬레이터에 올려 배치 하나를 만들고, 메모 입력창을 띄우고, 할일 선택 시트와 서랍을 열고, 할일 탭과 상세로 들어가고, 가로로 돌렸다. 전부 동작했다.

이유는 단순했다. 타임라인의 블록 폭은 처음부터 "뷰포트 폭에서 시간축과 스크롤바 레인을 뺀 값" 이었고, 주간 스트립은 칸 일곱 개를 `HStack` 이 균등하게 나눠 갖고, 월 격자와 잔디도 컨테이너 폭을 읽어 칸 크기를 정한다. 코드 어디에도 `UIScreen.main` 이나 기기 종류를 묻는 줄이 없었다. 시트는 iPadOS 가 알아서 가운데 form 시트로 띄웠고, 메모 입력창은 아이폰과 같이 키보드 위에 붙었다.

![가로 아이패드의 플래너 — 블록이 창 폭을 그대로 채운다](/blog/planner-ipad/landscape-planner.png)

그래서 "아이패드 대응" 은 화면을 새로 짓는 일이 아니라, 창 크기를 가정한 자리 둘을 찾아 고치는 일이 됐다.

## 분기 축은 창 폭 하나

원칙부터 정했다. **기기로 가르지 않는다.** `userInterfaceIdiom == .pad` 같은 분기는 하나도 넣지 않는다. 아이패드에서 Split View 로 1/3 창을 열면 폭이 320pt 다 — 아이패드지만 아이폰 폭이다. 반대로 아이폰 Pro Max 를 눕히면 regular 폭이 된다. 기기는 창 크기를 말해 주지 않는다.

같은 이유로 size class 로 뷰 트리를 갈아 끼우지도 않는다. `if regular { A } else { B }` 로 두 트리를 두면 창 폭이 바뀌는 순간 뷰의 정체성이 갈려 그 안의 상태(선택·검색어)가 초기화된다. 달라져야 하는 것은 **값**뿐이다 — `.frame(maxWidth: 700).frame(maxWidth: .infinity)` 처럼, 좁은 창에서는 아무 일도 안 하고 넓은 창에서만 가운데로 모이는 식으로.

이 원칙으로 할일 탭을 손봤다. 목록에만 700pt 상한이 걸려 있어서 세그먼트·제목은 전폭인데 목록만 좁았고, 가로 창에서는 목록의 회색 배경이 흰 여백 사이에 띠로 남았다. 세그먼트와 목록을 한 열로 묶어 같은 폭으로 가운데 세우고, 배경은 컨테이너가 전폭으로 칠하게 했다.

타임라인은 손대지 않았다. 넓은 창에서도 하루 판은 창 폭을 다 채운다. 가운데 열로 좁히는 안은 남는 여백이 종이처럼 보이고, 우하단의 서랍 과녁과 좌하단의 되돌리기가 판에서 멀어져서 뺐다. 캘린더나 미리 알림의 일 보기도 전폭이다.

## 정작 고장 나 있던 것은 창 둘의 상태였다

빌드 설정에는 `UIApplicationSupportsMultipleScenes` 가 켜져 있었다. 아이패드에서 같은 앱 창을 둘 열 수 있다는 뜻이다. 그런데 "보고 있는 날", "선택된 블록", "어느 시트가 떠 있나" 같은 화면 상태가 `App` 구조체의 `@State` 에 있었다.

`App` 의 `@State` 는 창마다 하나가 아니다. 앱에 하나이고, 모든 창이 나눠 쓴다. 그래서 창 둘을 열면 거울이 된다 — 한 창에서 내일로 넘기면 다른 창도 내일로 넘어가고, 한 창에서 블록을 고르면 다른 창에서도 골라진다. 시뮬레이터로 확인하기 전까지는 코드만 봐서는 안 보이는 종류의 버그다.

고치는 방법은 상태를 한 단 내리는 것이다. `WindowGroup` 안에 창 루트 뷰를 하나 두고, 거기서 `@State` 로 화면 상태를 만들어 아래로 내려보낸다. 창이 하나 열릴 때마다 이 뷰가 새로 만들어지므로 상태도 창마다 생긴다. 앱에 정말 하나여야 하는 것 — 저장소, 설정, 되돌리기 스택, 알람 인박스 — 만 싱글턴으로 남긴다.

![새 창은 오늘을 보고, 원래 창은 어제 만든 배치를 그대로 본다](/blog/planner-ipad/new-window-today.png)

프로브로 확인했다. 첫 창에서 어제로 가 배치를 하나 만들고, 메뉴 바의 윈도우 ▸ 새로운 윈도우로 창을 열었다. 새 창은 오늘을 보여 줬고 어제의 배치는 첫 창에만 있었다. 상단 반쪽으로 타일링하고, 창 모서리를 끌어 375pt 까지 줄여도 탭 바가 아래로 내려오는 것 말고는 아이폰과 같은 화면이었다.

## 남은 것

되돌리기 스택은 앱에 하나라 다른 창에서 한 일도 되돌린다 — 저장소가 하나이니 일관되긴 하다. 트랙패드 호버와 하드웨어 키보드 단축키는 아직 없고, 시뮬레이터로는 잴 수도 없어서 실기에서 볼 일이다. UI 테스트가 탭 바를 `tabBars` 로 찾던 것은 iPadOS 26 의 상단 탭 바에서 잡히지 않아 라벨로 찾는 폴백을 넣었다.
