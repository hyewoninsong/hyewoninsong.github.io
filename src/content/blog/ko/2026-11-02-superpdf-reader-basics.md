SuperPDF 는 이제 긴 책 안에서 길을 잃지 않는다. 목차로 장을 찾고, 쪽 번호를 눌러 원하는 쪽으로 가고, 작은 스캔 글자는 넘겨 보는 채로 손가락으로 벌려 읽는다.

그동안 밑줄과 맵에만 힘을 쓰느라 PDF 리더라면 당연히 있어야 할 것들이 비어 있었다. 쪽을 옮기는 길이 넘기기와 검색뿐이었고, 작은 글씨를 키우려면 보는 방식 자체를 바꿔야 했다.

## 읽는 중에 필요한 것은 전부 아랫줄에 있다

| 하고 싶은 것 | 이제 하는 법 |
|---|---|
| 장을 찾기 | 목차 버튼 → 지금 읽는 장이 표시된 목록 |
| 다시 볼 쪽 표시 | 책갈피 버튼, 목차 옆 탭에 모임 |
| 멀리 있는 쪽으로 | "42 / 320" 을 눌러 슬라이더나 숫자로 이동 |
| 작은 글자 읽기 | 쪽을 두 손가락으로 벌리기, 두 번 탭 |
| 다음 검색 결과 | 판 아래 `‹ 3 / 17 ›` 막대, ⌘G |
| 밤에 읽기 | 쪽 색을 원본·세피아·밤에서 고르기 |

## 확인을 묻는 대신 되돌릴 수 있게 했다

책 삭제는 "되돌릴 수 없어요" 알림을 없애고, 카드가 바로 사라진 뒤 6초 동안 되돌리기 토스트를 띄운다. 알림은 습관적으로 눌러 넘기게 되는데, 잘못 누른 값은 밑줄과 맵 전부였다.

- **저장소에 "지운 표시"를 남기는 방식**은 탈락했다. 스키마를 바꿔야 하고, 앱이 죽으면 책이 숨은 채로 남는다. 지금은 메모리에서만 숨기므로 앱이 죽으면 책이 다시 나타난다. 틀려도 데이터를 잃지 않는 쪽이다.
- **알림과 토스트를 둘 다 두는 방식**도 탈락했다. 같은 확인을 두 번 받을 뿐이다.

처음엔 앱이 활성 상태를 벗어나면 바로 삭제를 확정했다. 그러면 제어 센터를 살짝 내리기만 해도 되돌릴 기회가 사라져서, 진짜 백그라운드로 갈 때만 확정하도록 고쳤다.

책갈피도 같은 기준으로 정했다. 스키마를 올리면 동결한 모델 여섯 개가 어긋날 위험이 있어, 파일별 작은 JSON 에 담았다. 옛 저장소는 건드리지 않는다.

## 두 번 탭을 넣자 넘김이 0.3초 늦어졌다

두 번 탭 확대를 붙였더니 쪽 가장자리를 탭해서 넘기는 동작이 0.3초 늦어졌다. 한 번 탭 인식기가 두 번 탭이 실패하기를 기다리기 때문이다. 이 앱은 빠른 넘김이 버벅이는 문제를 쪽을 미리 그려 두는 구조로 고친 적이 있어서, 그 지연은 받아들일 수 없었다.

해법은 구역을 나누는 것이다. 두 번 탭은 판 가운데 60% 에서만 받는다. 가장자리 탭은 기다리지 않고 바로 넘기고, 쪽이 확대된 동안에만 어디서든 받는다. 넘김 탭이 그때는 꺼져 있기 때문이다.

확대가 원래 쪽 크기 안에 갇혀 위아래로 빈 띠가 남는 문제도 있었다. 책장 넘김은 쪽 컨트롤러의 뷰 전체를 말기 때문에, 여백이 같이 말리지 않도록 뷰를 쪽 비율로 줄여 두었던 것이 원인이었다. 이제 확대 중에만 잘라내기를 풀고, 원래 크기로 돌아오면 다시 건다.

## 18번 중 12번만 나타난 축소 화면

밤 쪽 스크린샷 한 장에서 스크롤 화면이 세 쪽이나 보일 만큼 작아져 있었다. 처음엔 캡처가 잘못된 줄 알았다. 같은 조건으로 18번씩 돌려 보니, 바뀐 브랜치는 12번 작게 떴고 main 은 한 번도 그러지 않았다. 원본 톤에서도 재현됐으니 밤 쪽 탓이 아니었다.

`PDFView` 의 첫 맞춤은 비동기로 돌아가는데, 그때 뷰가 아직 창에 붙지 않아 폭이 0 이면 조용히 건너뛴다. 나중에 폭이 바뀌면 다시 맞춰 주는 경로가 있지만, 그 경로는 "한 번이라도 맞춘 뷰"만 받았다. 그래서 첫 맞춤을 놓친 뷰는 복구할 길이 없었다. 설정값을 읽는 구독이 하나 늘자 갱신 순서가 바뀌어 이 틈이 드러났다. 복구 경로가 아직 못 맞춘 상태도 받도록 고쳤더니 18번 모두 정상이었다.

한 번 찍은 화면이 맞아 보여도 타이밍 문제는 숨어 있을 수 있다. 배율이 이상하면 같은 조건으로 여러 번 돌려 비율을 재 보는 편이 빠르다.

## 남은 것

두 쪽 펼침 확대와 실제 손가락 핀치, 햅틱은 시뮬레이터로 확인할 수 없어 기기에서 봐야 한다.
