친구 시간표를 받아 보기 시작한 뒤로, 기기를 잠깐 내려놓을 때 이 앱만 따로 가리고 싶다는 요구가
생겼다. 기기 자체 잠금에만 기대면 "기기는 풀려 있는데 이 앱은 가리고 싶다"는 경우를 못 받는다.
그래서 설정에 Face ID / Touch ID / 암호 잠금을 하나 달았다. 기본은 꺼짐이고, 켜면 앱을 백그라운드로
보냈다가 돌아올 때 창 전체를 덮는 잠금 화면이 뜬다.

(2026-10-08: 이 기능은 나흘 뒤에 뺐다. 지금 앱에는 앱 잠금이 없다 — 맨 아래 "나흘 만에 뺐다" 절.
아래는 달고 고치던 동안의 기록이다.)

## 켜고 끌 때 모두 인증부터

토글은 탭한다고 바로 켜지지 않는다. 켜는 쪽으로 넘기면 먼저 인증을 요구하고, 통과해야 실제로
켜진다. 끄는 쪽도 마찬가지다 — 잠가 놓고 본인도 못 푸는 사고, 남이 슬쩍 꺼 버리는 사고를
둘 다 막으려면 어느 방향이든 본인 확인이 먼저여야 한다. 켜져 있을 때만 유예 시간 칩(즉시 / 1분 /
5분)이 아래 나타난다 — 즉시는 백그라운드에서 돌아올 때마다 다시 묻고, 5분은 짧은 외출 정도는
봐준다.

![잠금 화면(라이트) — Face ID 아이콘, "시간표가 잠겼습니다", 잠금 해제 캡슐](/blog/timetable-biometric-app-lock/lock-screen-light.png)
![잠금 화면(다크) — 같은 구성이 다크 모드에서도 그대로 유지된다](/blog/timetable-biometric-app-lock/lock-screen-dark.png)

잠긴 화면은 자물쇠가 아니라 기기의 생체 종류를 그대로 보여준다. Face ID 기기면 Face ID 아이콘과
글자, Touch ID 기기면 Touch ID로 바뀐다. 이 세 이름(Face ID / Touch ID / Optic ID)은 애플이 쓰는
고유 명사라 어느 언어판에서도 번역하지 않았다 — 그 밖의 설명 문장만 로케일을 따른다.

## 질문은 둘인데, 깃발은 하나면 됐다

구현하면서 "지금 가려야 하는가"를 묻는 시점이 사실 두 개라는 걸 알았다.

하나는 **앱 스위처 썸네일**이다. iOS는 앱이 비활성으로 넘어가는 순간(`scenePhase`가 `.inactive`로
바뀌는 순간) 화면을 찍어 둔다. 유예 시간이 5분이든 즉시든 상관없이, 그 순간 시간표가 그대로
찍히면 안 된다. 다른 하나는 **재인증 여부**다. 앱이 완전히 백그라운드로 내려갔다가(`.background`)
다시 돌아올 때, 유예 시간이 지났으면 다시 인증을 요구하고 안 지났으면 그냥 넘어간다.

처음엔 이 둘을 각각 다른 상태값으로 만들려고 했다. 그런데 둘 다 결과적으로 "지금은 콘텐츠를
보여주면 안 된다"는 같은 화면(불투명 오버레이)으로 수렴한다 — 스위처를 열었다 바로 돌아오면
(`.background`를 거치지 않았으면) 오버레이가 잠깐 떴다가 재인증 없이 곧바로 내려가고, 유예가
지났으면 그 오버레이가 인증을 요구하는 화면으로 그대로 남는다. 그래서 `isLocked` 플래그 하나로
합쳤다. 나뉘는 건 "언제 true가 되는가"(`.inactive`에서는 유예 무관 즉시, `.active`로 돌아올 때는
유예 판정 함수로)뿐이고, 그 판정 자체는 `shouldLock(lockedAt:now:grace:)`라는 순수 함수 하나로
뺐다 — 입력 세 개, 출력 하나라 단위 테스트가 그대로 경계값을 확인한다.

(2026-10-05: 이 판단은 하루 만에 뒤집혔다. 지금은 가림과 인증 요구가 별개 상태다 — 아래
"깃발 하나로는 안 됐다" 절.)

토글 쪽도 비슷한 결로 풀었다. SwiftUI의 커스텀 `Binding`으로 "인증 통과해야 값이 바뀐다"를 짜면
자연스러워 보이지만, 이 앱은 전에 세그먼트 피커에서 커스텀 `Binding`의 `set` 안에 다른 상태 변경을
같이 넣었다가 탭이 가끔 씹히는 경쟁 상태를 겪은 적이 있다. 그래서 토글도 로컬 상태를 그대로
바인딩하고, 값이 바뀌는 순간을 `.onChange`에서 받아 인증 결과를 기다린 뒤에만 실제 설정값을
바꾸는 쪽으로 갔다. 인증이 끝나기 전까지 토글은 눈에 보이게 움직이지 않는다 — 시스템 Face ID
연출이 뜨는 동안 사용자가 보는 건 "아직 안 켜졌다"는 상태 그대로다.

## 알람은 잠금 위에서 울린다

같은 날 알람 배너 쪽 애니메이션을 손보는 변경이 같은 파일에 들어오고 있었다. 겹치는 자리를
건드리지 않으려고, 잠금 오버레이는 별도 레이어로 얹고 알람 배너가 그 위에 그려지게 선언 순서만
정했다. 울리는 알람은 꺼야 하는 손잡이니까 잠긴 상태에서도 눌려야 한다 — 그래서 일정 제목은
가리지 않고 그대로 보여주기로 했다. "일정"이라는 말로 대체하는 길도 있었지만, 배너 하나 때문에
새 상태값을 또 만드는 것치고는 득이 적어 보류했다.

(2026-10-07: 잠금 화면은 이제 같은 뷰 트리의 레이어가 아니라 전용 창이다. 배너가 잠금 위라는 규칙은
그대로고, 그리는 자리만 바뀌었다 — 아래 "모든 것 위는 뷰 계층의 약속이 아니었다" 절.)

그리고 그 변경 덕분에 같은 함정을 하나 먼저 피할 수 있었다. 오버레이는 `.transition(.opacity)`로
나타나고 사라지는데, `isLocked` 값을 평범하게 대입만 하면 전환이 재생되지 않는다. `.transition`은
뷰가 트리에서 삽입/제거될 때 재생되고, 그 삽입/제거를 일으키는 상태 변경이 애니메이션 트랜잭션
안에서 일어나야 하기 때문이다. 옆에서 알람 배너가 겪고 고친 게 정확히 같은 증상이었다 — 그래서
내 쪽도 처음부터 `isLocked` 대입을 `withAnimation`으로 감싸 넣었다. 뷰 쪽에 `.animation(value:)`를
거는 방식은 조건부 등장/퇴장에는 신뢰할 수 있게 안 걸린다는 걸 같은 날 두 번 확인한 셈이다.

(2026-10-07: 잠금 화면의 등장은 이제 곡선 없이 즉시고, 내려갈 때의 페이드는 전용 창이 한다.)

## 남은 것

처음 올릴 때는 시뮬레이터에서 Face ID 등록을 켤 방법이 메뉴뿐이라고 보고, 잠금 화면이 뜨고
애니메이션이 재생되는 것까지만 확인했다. 그 공백이 바로 다음 날 제보로 돌아왔다(아래 절). 지금은
인증 창이 실제로 뜨는 켜기·끄기 왕복을 시뮬레이터 UI 테스트가 돈다. 콜드 런치 취소와 유예 재방문
구멍은 상태 테스트로만 확인했고, 실기기에서는 아직 돌려 보지 않았다.

## 2026-10-05 — 깃발 하나로는 안 됐다: Face ID 창도 앱을 비활성으로 만든다

하루 만에 실기기에서 제보가 왔다. 잠금을 끄려고 토글을 넘기면 Face ID 가 통과하는데도 "인증 실패"
알럿이 뜨고, 토글은 켜진 자리로 돌아간다. 켜는 쪽은 멀쩡했다.

![설정 시트 위에 뜬 "인증 실패" 알럿 — 앱 잠금 토글은 여전히 켜져 있다](/blog/timetable-biometric-app-lock/auth-failed-alert.png)

원인은 위에서 내린 바로 그 판단이었다. 시스템이 띄우는 Face ID 창은 앱 창 위에 얹히는 시스템 UI 라,
뜨는 것만으로 `scenePhase` 가 `.inactive` 가 되고 닫히면 `.active` 로 돌아온다. 성공이든 취소든
같다. 그러니 `.inactive` 에서 화면을 가리는 잠금은 **자기가 띄운 인증 때문에도** 그 길을 탄다.

| # | 일어난 일 |
|---|---|
| 1 | 토글을 끈다 → 설정이 인증 창을 띄운다 |
| 2 | 씬이 `.inactive` → 스냅샷을 가리려고 `isLocked = true` |
| 3 | 잠금 화면이 뜬다 → 잠금 화면은 뜨면 자동으로 인증을 시도한다 |
| 4 | 두 번째 인증이 첫 번째와 겹친다 → 설정 쪽 인증이 실패로 돌아온다 |

켤 때는 잠금이 아직 꺼져 있어 2번이 일어나지 않는다. 그래서 끌 때만 터졌다.

같은 뿌리의 구멍이 둘 더 있었다. 앱을 새로 켜서 잠긴 화면에서 Face ID 를 취소하면, 뒤따라 오는
`.active` 가 "스위처만 잠깐 봤구나" 로 읽고 잠금을 내렸다. 유예를 1분이나 5분으로 둔 경우에는,
잠긴 뒤 인증하지 않고 백그라운드에 한 번 더 다녀오면 기준 시각이 새로 찍혀 유예 안으로 판정됐다.
둘 다 잠금 화면이 인증 없이 사라지는 길이다.

### 화면 결과가 같아도, 내릴 자격이 다르면 다른 상태다

상태를 둘로 나눴다.

| | 가림 | 풀려면 인증 |
|---|---|---|
| 올리는 순간 | 비활성·백그라운드, 런치 잠금, 유예 경과 | 런치 잠금, 유예 경과만 |
| 내리는 순간 | 복귀(인증 요구가 없을 때), 인증 성공 | 인증 성공만 |

잠금 화면의 자동 인증은 "가려졌다" 가 아니라 "인증이 필요해졌다" 를 보고 뜬다. 복귀 판정은 인증
요구가 서 있으면 아무것도 하지 않는다. 인증 호출은 겹쳐 뜨지 않게 막았다. 덤으로 제어 센터를 내렸다
올릴 때마다 Face ID 가 뜨던 것도 없어졌다.

진 대안은 둘이다. 설정 인증이 떠 있는 동안만 가림을 건너뛰는 길은 증상만 가리고, 인증 창이 뜬 채
스위처로 가면 썸네일이 안 가려진다. 인증을 한 줄로 세우기만 하는 길은 설정 인증은 살리지만 나머지
두 구멍이 그대로다.

### 왜 못 잡았나, 그리고 이제 무엇이 잡나

처음 검증은 잠금 화면 캡처(자동 인증을 끈 상태)와 유예 판정 함수 테스트였다. 인증 창이 실제로 뜨는
길은 한 번도 돌지 않았다. 켜기만 손으로 해 봐도 통과한다 — 잠금이 켜진 상태에서 인증을 띄우는
설정 경로는 끄기 하나뿐이다.

시뮬레이터에서도 이 길을 돌릴 수 있었다. Face ID 등록과 매칭은 Darwin 알림이고, UI 테스트 러너는
같은 시뮬레이터 안에서 도니 `notify_post` 로 직접 쏠 수 있다. 등록은
`com.apple.BiometricKit.enrollmentChanged` 의 상태를 1 로 두고 알리고, 통과는
`com.apple.BiometricKit_Sim.pearl.match` 다. 토글을 켰다 끄는 테스트를 수정 전 코드에 돌리면 끈 뒤
알럿 1개에 토글이 그대로였고, 수정 후에는 알럿 0개에 토글이 꺼졌다.

씬 전환 순서는 따로 고정했다. 잠금 상태 객체가 설정·인증·시계를 주입받게 바꾸고, 인증이 진행되는
동안 비활성과 복귀를 차례로 부르는 테스트를 넣었다. 취소로 통과하던 구멍과 유예 구멍은 이쪽이 지킨다.


## 2026-10-07 — "모든 것 위" 는 뷰 계층의 약속이 아니었다: 잠금 화면이 시트 밑에 깔려 있었다

설정 시트를 연 채로 기기를 잠갔다 풀면 Face ID 는 도는데 잠금 화면이 안 보이고 설정이 그대로
보인다는 제보가 왔다. 곧이어 스크린샷이 하나 더 왔다. 툴바 메뉴를 연 채로 잠그면, 메뉴가 잠금 화면
위에 그대로 떠 있다.

![잠금 화면 위에 그대로 떠 있는 툴바 메뉴 — 설정·공유·인쇄 행이 "시간표가 잠겼습니다" 를 덮고 있다](/blog/timetable-biometric-app-lock/menu-over-lock.png)

잠금 상태는 멀쩡히 돌고 있었다. 잠겼고, 잠금 화면도 그려졌고, 자동 인증도 떴다. 화면만 가려져
있었다. 잠금 화면은 창 루트 `ZStack` 의 맨 위 레이어였는데, SwiftUI 의 `.sheet` · `.alert` ·
`.popover` · `Menu` 는 그 뷰 트리의 형제가 아니라 루트 위에 따로 얹히는 프레젠테이션이다. 루트 안에서
`zIndex` 를 얼마로 주든 순서가 바뀌는 건 루트 안에서뿐이다. 처음 글에 "창 전체를 덮는 잠금 화면" 이라고
썼지만, 실제로 보장된 건 "루트 콘텐츠 위" 까지였다.

### 잠금 화면을 창으로 올렸다

잠금 화면을 씬마다 전용 `UIWindow` 로 옮겼다. 창 레벨은 일반 창 위(`.alert + 1`)다. 씬 루트 배경에
숨은 `UIView` 하나를 깔아 두고, 그 뷰가 자기가 붙은 `UIWindowScene` 을 찾아 창을 올리고 내린다.
아이패드에서 창이 여럿이면 창마다 하나씩 생긴다.

![설정 시트를 연 채 나갔다 돌아온 화면 — 잠금 화면이 시트를 전부 덮고, 그 위에 Face ID 창이 떠 있다](/blog/timetable-biometric-app-lock/lock-over-sheet.png)

옮기면서 정한 것들:

| | 정한 것 | 이유 |
|---|---|---|
| 등장 | 곡선 없이 즉시 | 앱 스위처 썸네일이 찍히기 전에 불투명해야 한다 |
| 퇴장 | 0.25초 페이드 | 인증 직후 화면이 툭 바뀌지 않게 |
| 알람 배너 | 잠금 창이 제 위에 한 번 더 그린다 | 루트의 배너는 이제 창에 가려진다. 소리는 잠긴 채로도 꺼야 한다 |
| 키보드 | 인증이 필요한 잠금이면 내린다 | 가려진 입력란에 글자가 들어가면 안 된다 |
| 풀린 뒤 | 떠 있던 시트·메뉴는 그대로 | 편집하던 내용을 잠금이 날리면 안 된다 |

전용 창은 씬 루트의 SwiftUI 환경을 물려받지 않는다. 앱의 라이트/다크 설정은 창의
`overrideUserInterfaceStyle` 로 따로 넘겼다.

진 대안은 둘이다. 시트마다 잠금 레이어를 얹는 길은 시트·알럿·팝오버가 수십 곳이라 새로 생기는 자리마다
빠지고, 시스템 메뉴에는 얹을 수도 없다. 잠길 때 떠 있는 것을 전부 닫는 길은 쓰던 내용을 날린다.

### 덮개의 증거는 "있다" 가 아니라 "밑의 것이 안 눌린다" 다

이틀 전에 만든 Face ID 왕복 테스트는 설정 시트 안에서 돌았다. 그런데도 못 잡았다. 그 테스트가 본 것은
토글 값과 알럿 수, 그리고 잠금 화면의 **존재**였다. 시트 밑에 깔린 잠금 화면도 접근성 트리에는 있다.

새 테스트는 `isHittable` 을 본다. 시트를 연 채, 메뉴를 연 채로 각각 홈으로 나갔다 돌아와서 잠금 해제
버튼이 눌리는지, 그 밑의 설정 토글과 메뉴 행이 안 눌리는지를 확인한다. 수정 후 시뮬레이터에서 두 경우
모두 해제 버튼은 눌리고 밑의 요소는 안 눌렸다. 수정 전 코드로는 이 테스트를 돌리지 않았다 — 수정 전
증거는 위 스크린샷이다.

아직 안 돌린 길이 있다. 아이패드 멀티윈도우, 알람이 울리는 중에 잠기는 경우, 키보드가 올라온 채
잠기는 경우, 그리고 실기기다.


## 2026-10-08 — 나흘 만에 뺐다: 유예가 화면에서는 안 지켜졌고, 풀 방법 전부를 확인할 길이 없었다

앱 잠금을 통째로 뺐다. 설정의 토글, 잠금 유예 칩, 잠금 화면, 전용 창까지 전부다. 설정 카드
"잠금 및 백업" 은 iCloud 백업 한 행만 남아 "백업" 이 됐다. 잠금을 켜 두었던 사람은 업데이트하면
잠금 없이 열린다.

### 고쳐서 남기지 않은 이유

실기기에서 쓰면서 두 가지가 걸렸다.

**유예를 5분으로 둬도 잠금 화면이 한 번 보였다.** 앱을 잠깐 나갔다 돌아오면 잠금 화면이 덮였다가
걷힌다. 위 절들에서 만든 구조가 그대로 드러난 것이다 — 앱 스위처 썸네일을 가리려면 `.inactive` 에서
먼저 덮어야 하고, 유예 판정은 `.active` 로 돌아온 뒤에야 한다. 그 사이가 눈에 보인다. 유예 안쪽이라
인증은 안 묻지만, "5분은 봐준다" 고 약속한 화면이 돌아올 때마다 한 번 깜빡인다.

**Face ID 말고 나머지 길을 확인할 수단이 없었다.** 풀 방법은 Face ID, Touch ID, 기기 암호 셋이어야
한다. 시뮬레이터에서 자동으로 돌릴 수 있었던 건 Face ID 매칭뿐이다. 암호 입력 화면은 테스트가
넘기지 못하고, Touch ID 는 그 기기가 있어야 한다. 나흘 동안 제보가 두 번 왔고 둘 다 "검증이 안 돈 길"
에서 나왔다. 잠금은 틀리면 본인이 못 들어가거나 남이 들어오는 기능이라, 안 돌려 본 길을 남긴 채
둘 수가 없다.

진 대안은 둘이다. 첫 문제만 고치는 길(유예 안쪽이면 덮지 않기)은 썸네일이 그대로 찍힌다 —
가리는 게 이 기능의 절반이었다. 유예를 없애고 "즉시" 만 남기는 길은 첫 문제를 지우지만 두 번째가
그대로다. 시간표는 기기 잠금이 이미 지키는 정보라는 점까지 놓고 보면, 남길 만큼의 값이 아니었다.

### 같이 사라진 것 — 토글할 때 설정 시트가 줄었다 늘어났다

잠금을 켜거나 끌 때 설정 시트 전체가 안쪽으로 줄어 테두리 바깥이 보였다가 되돌아오는 증상도 있었다.

![Face ID 인증 중인 설정 시트 — 시트가 화면 폭을 가득 채우고 있다](/blog/timetable-biometric-app-lock/sheet-during-auth.png)
![인증 직후 — "잠금 유예" 행이 생긴 순간, 시트 전체가 줄어 사방 가장자리가 떠 있다](/blog/timetable-biometric-app-lock/sheet-shrunk-after-auth.png)

두 화면의 차이는 행 하나다. 인증이 통과하면 "잠금 유예" 행이 카드에 생긴다. 이 시트는 콘텐츠 높이를
실측해 그 값으로 `.height` detent 를 정하는데, 행이 생기면 실측 높이가 바뀌고 detent 가 새 값으로
옮겨 간다. 설정 시트는 화면보다 길어서 옛 높이도 새 높이도 화면 상한에 잘린다. 결과 높이는 같은데,
선택된 detent 가 바뀌는 동안 iOS 26 시트가 부분 높이 모양(가장자리가 뜨는 축소)을 한 번 거쳤다
돌아온 것으로 읽었다.

기능을 빼면서 그 행과 토글이 같이 없어져 이 경로는 사라졌다. 다만 이 설명은 스크린샷과 코드에서
읽은 것이고, 따로 재현해 확정하지는 않았다. "화면보다 긴 시트의 실측 높이가 바뀐다" 는 조건은
캡션이 한 줄에서 두 줄로 바뀌는 경우처럼 다른 자리에 남아 있다.

### 남은 것

위 절들의 두 메커니즘 — 시스템 인증 창이 씬을 비활성으로 만든다, 루트 레이어는 시트 밑에 깔린다 —
은 기능과 상관없이 맞는 이야기라 기록으로 남겼다. 잠금을 다시 단다면 조건은 둘이다. 유예 안쪽
복귀에서 잠금 화면이 한 프레임도 보이지 않을 것, 그리고 세 인증 수단을 전부 돌려 볼 수단이 먼저
있을 것.
