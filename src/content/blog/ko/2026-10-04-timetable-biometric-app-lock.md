친구 시간표를 받아 보기 시작한 뒤로, 기기를 잠깐 내려놓을 때 이 앱만 따로 가리고 싶다는 요구가
생겼다. 기기 자체 잠금에만 기대면 "기기는 풀려 있는데 이 앱은 가리고 싶다"는 경우를 못 받는다.
그래서 설정에 Face ID / Touch ID / 암호 잠금을 하나 달았다. 기본은 꺼짐이고, 켜면 앱을 백그라운드로
보냈다가 돌아올 때 창 전체를 덮는 잠금 화면이 뜬다.

## 켜고 끌 때 모두 인증부터

토글은 탭한다고 바로 켜지지 않는다. 켜는 쪽으로 넘기면 먼저 인증을 요구하고, 통과해야 실제로
켜진다. 끄는 쪽도 마찬가지다 — 잠가 놓고 본인도 못 푸는 사고, 남이 슬쩍 꺼 버리는 사고를
둘 다 막으려면 어느 방향이든 본인 확인이 먼저여야 한다. 켜져 있을 때만 유예 시간 칩(즉시 / 1분 /
5분)이 아래 나타난다 — 즉시는 백그라운드에서 돌아올 때마다 다시 묻고, 5분은 짧은 외출 정도는
봐준다.

![잠금 화면(라이트) — Face ID 아이콘, "시간표가 잠겼습니다", 잠금 해제 캡슐](/blog/timetable-biometric-app-lock/lock-screen-light.png)
![잠금 화면(다크) — 같은 구성이 다크 모드에서도 그대로 유지된다](/blog/timetable-biometric-app-lock/lock-screen-dark.png)

잠긴 화면은 자물쇠가 아니라 기기의 생체 종류를 그대로 보여준다. Face ID 기기면 Face ID 아이콘과
글자, Touch ID 기기면 Touch ID로 바뀐다. 이 세 이름(Face ID / Touch ID / Optic ID)은 애플이 쓰는
고유 명사라 어느 언어판에서도 번역하지 않았다 — 그 밖의 설명 문장만 로케일을 따른다.

## 질문은 둘인데, 깃발은 하나면 됐다

구현하면서 "지금 가려야 하는가"를 묻는 시점이 사실 두 개라는 걸 알았다.

하나는 **앱 스위처 썸네일**이다. iOS는 앱이 비활성으로 넘어가는 순간(`scenePhase`가 `.inactive`로
바뀌는 순간) 화면을 찍어 둔다. 유예 시간이 5분이든 즉시든 상관없이, 그 순간 시간표가 그대로
찍히면 안 된다. 다른 하나는 **재인증 여부**다. 앱이 완전히 백그라운드로 내려갔다가(`.background`)
다시 돌아올 때, 유예 시간이 지났으면 다시 인증을 요구하고 안 지났으면 그냥 넘어간다.

처음엔 이 둘을 각각 다른 상태값으로 만들려고 했다. 그런데 둘 다 결과적으로 "지금은 콘텐츠를
보여주면 안 된다"는 같은 화면(불투명 오버레이)으로 수렴한다 — 스위처를 열었다 바로 돌아오면
(`.background`를 거치지 않았으면) 오버레이가 잠깐 떴다가 재인증 없이 곧바로 내려가고, 유예가
지났으면 그 오버레이가 인증을 요구하는 화면으로 그대로 남는다. 그래서 `isLocked` 플래그 하나로
합쳤다. 나뉘는 건 "언제 true가 되는가"(`.inactive`에서는 유예 무관 즉시, `.active`로 돌아올 때는
유예 판정 함수로)뿐이고, 그 판정 자체는 `shouldLock(lockedAt:now:grace:)`라는 순수 함수 하나로
뺐다 — 입력 세 개, 출력 하나라 단위 테스트가 그대로 경계값을 확인한다.

토글 쪽도 비슷한 결로 풀었다. SwiftUI의 커스텀 `Binding`으로 "인증 통과해야 값이 바뀐다"를 짜면
자연스러워 보이지만, 이 앱은 전에 세그먼트 피커에서 커스텀 `Binding`의 `set` 안에 다른 상태 변경을
같이 넣었다가 탭이 가끔 씹히는 경쟁 상태를 겪은 적이 있다. 그래서 토글도 로컬 상태를 그대로
바인딩하고, 값이 바뀌는 순간을 `.onChange`에서 받아 인증 결과를 기다린 뒤에만 실제 설정값을
바꾸는 쪽으로 갔다. 인증이 끝나기 전까지 토글은 눈에 보이게 움직이지 않는다 — 시스템 Face ID
연출이 뜨는 동안 사용자가 보는 건 "아직 안 켜졌다"는 상태 그대로다.

## 알람은 잠금 위에서 울린다

같은 날 알람 배너 쪽 애니메이션을 손보는 변경이 같은 파일에 들어오고 있었다. 겹치는 자리를
건드리지 않으려고, 잠금 오버레이는 별도 레이어로 얹고 알람 배너가 그 위에 그려지게 선언 순서만
정했다. 울리는 알람은 꺼야 하는 손잡이니까 잠긴 상태에서도 눌려야 한다 — 그래서 일정 제목은
가리지 않고 그대로 보여주기로 했다. "일정"이라는 말로 대체하는 길도 있었지만, 배너 하나 때문에
새 상태값을 또 만드는 것치고는 득이 적어 보류했다.

그리고 그 변경 덕분에 같은 함정을 하나 먼저 피할 수 있었다. 오버레이는 `.transition(.opacity)`로
나타나고 사라지는데, `isLocked` 값을 평범하게 대입만 하면 전환이 재생되지 않는다. `.transition`은
뷰가 트리에서 삽입/제거될 때 재생되고, 그 삽입/제거를 일으키는 상태 변경이 애니메이션 트랜잭션
안에서 일어나야 하기 때문이다. 옆에서 알람 배너가 겪고 고친 게 정확히 같은 증상이었다 — 그래서
내 쪽도 처음부터 `isLocked` 대입을 `withAnimation`으로 감싸 넣었다. 뷰 쪽에 `.animation(value:)`를
거는 방식은 조건부 등장/퇴장에는 신뢰할 수 있게 안 걸린다는 걸 같은 날 두 번 확인한 셈이다.

## 남은 것

시뮬레이터에는 "Face ID 등록됨"을 토글로 켜는 명령이 없다(Simulator.app의 Features 메뉴뿐이다).
그래서 이번 검증은 잠금 화면 자체가 뜨고, 애니메이션이 재생되고, 설정 UI가 올바로 동작하는
것까지였다. 실제 인증 성공/취소에 따라 토글이 켜지거나 원래대로 돌아가는 흐름은 실기기 확인이
더 필요하다.
