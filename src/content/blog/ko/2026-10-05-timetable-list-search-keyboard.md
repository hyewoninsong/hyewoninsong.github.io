시간표 목록에서 검색 필드를 누르면 키보드만 올라오게 고쳤다. 카드는 원래 크기 그대로 있고, 아래쪽이 키보드에 가릴 뿐이다. 그리고 같은 날 저녁, 카드형에서는 검색 필드 자체를 뺐다. 그 이야기는 맨 아래 절에 있다.

## 키보드가 올라오면 화면 전체가 다시 그려졌다

목록은 시간표를 카드 한 장씩 넘겨 보는 화면이다. 카드 높이는 남는 세로 공간을 재서 정한다. 그래서 키보드가 올라와 공간이 절반이 되면 카드도 절반 높이로 다시 그려졌다. 페이지 점과 "새 시간표" 버튼도 키보드 위로 따라 올라왔다. 검색어를 치려는 순간 보고 있던 그림이 바뀌는 셈이다.

![검색 전 — 카드가 시트를 가득 채운다](/blog/timetable-list-search-keyboard/list-idle.png)

![검색 필드를 누른 뒤 — 카드 크기는 그대로, 키보드가 아래를 덮는다](/blog/timetable-list-search-keyboard/list-keyboard.png)

제목 표시줄이 접힌 만큼 카드가 위로 올라가는 것은 시스템 검색의 기본 동작이라 그대로 뒀다.

## 수식어는 있었는데 자리가 틀렸다

코드에는 `.ignoresSafeArea(.keyboard)` 가 이미 있었다. 다만 `NavigationStack` 바깥에 걸려 있었다.

```swift
NavigationStack {
    VStack { … }              // 이 내용은 여전히 키보드를 피한다
}
.ignoresSafeArea(.keyboard)   // 스택 바깥 — 안쪽에는 닿지 않는다
```

바깥에 건 수식어는 스택 컨테이너에만 적용되고, 안쪽 내용은 자기 안전 영역을 따로 받는다. 수식어를 안쪽 `VStack` 으로 옮기자 카드가 움직이지 않았다. `.navigationTitle` 이나 `.searchable` 과 같은 자리다. 이 판단의 근거는 옮기기 전과 후의 화면이고, 프레임워크 내부를 확인한 것은 아니다.

왜 아무도 몰랐나. 그 수식어가 들어간 때에는 이 화면에 글자를 칠 곳이 없었다. 키보드가 뜰 일이 없으니 효과가 있는지 볼 방법도 없었다. 검색을 넣던 날에는 결과가 제대로 걸러지는지만 찍었고, 키보드가 떠 있는 화면은 찍지 않았다.

## 제목 목록은 일부러 그대로 뒀다

목록에는 카드 대신 제목만 늘어놓는 보기도 있다. 여기서는 키보드를 계속 피하게 했다. 피하지 않으면 키보드 밑에 깔린 줄까지 스크롤할 길이 없어서, 검색 결과가 많을 때 아래쪽을 볼 수 없다. 줄은 크기가 변하지 않으니 쪼그라드는 느낌도 없다.

정리하면 기준은 하나다. 남는 공간을 재서 크기를 정하는 그림은 키보드를 무시하고, 스크롤되는 목록은 키보드를 피한다.

## 남은 것

카드형에서는 키보드가 떠 있는 동안 "새 시간표" 버튼이 가려졌다. 검색 중에 새 시간표를 만들 일은 드물다고 보고 그대로 뒀는데, 저녁에 카드형 검색이 빠지면서 이 문제도 같이 사라졌다. 그리고 화면에 입력 칸을 새로 넣을 때는 키보드가 뜬 상태를 한 장 찍는 것을 확인 절차에 넣었다.

## 2026-10-05 저녁 — 카드형에서는 검색을 뺐다

키보드를 고친 화면을 실제 기기에서 보니 다른 것이 눈에 들어왔다. 카드형 상단에 닫기, 제목, 보기 전환, 편집이 한 줄, 그 아래 검색창이 또 한 줄이다. 카드 한 장을 보러 온 화면에 머리가 두 줄이면 복잡하다.

검색 필드는 이제 제목 목록에서만 보인다. 카드형 상단은 한 줄로 돌아갔다.

![카드형 — 상단이 한 줄이다](/blog/timetable-list-search-keyboard/cards-no-search.png)

![제목 목록 — 검색 필드가 제목 표시줄 바로 아래에 있다](/blog/timetable-list-search-keyboard/titles-search-top.png)

카드 넘김은 몇 장을 눈으로 훑는 화면이고, 이름으로 찾는 일은 목록 쪽에 어울린다. 카드형에서는 검색어를 무시하고, 카드형으로 돌아갈 때 검색어를 비운다. 보이지 않는 검색어가 카드를 거르면 안 되기 때문이다.

진 안은 셋이다.

- 검색을 돋보기 버튼으로 접고 보기 전환과 편집을 메뉴 하나로 묶기. 가장 많이 비지만 편집이 한 번 더 눌러야 나온다.
- 돋보기 버튼만 추가하기. 줄은 줄지만 오른쪽 버튼이 셋이 된다.
- 제목 목록에서도 접어 두고 당겨 내리면 나오게 하기. 접힌 필드는 있는 줄 모른다.

## 검색 필드가 화면 맨 아래로 갔다

제목 목록에만 달면 되니 `.searchable` 을 그 목록 뷰에 직접 걸었다. 그러자 필드가 제목 표시줄 아래가 아니라 화면 맨 아래, "새 시간표" 버튼 밑에 떴다.

![목록 뷰에 직접 걸었을 때 — 검색 필드가 맨 아래로 갔다](/blog/timetable-list-search-keyboard/titles-search-bottom.png)

```swift
// 필드가 화면 아래로 간다
case .titles: titleList.searchable(text: $query, placement: .navigationBarDrawer)

// 필드가 제목 표시줄 아래에 붙는다
VStack { … }
    .navigationTitle("시간표 목록")
    .modifier(TitleListSearch(isEnabled: style == .titles, text: $query))
```

위치를 정하는 인자는 같은데 걸린 자리에 따라 결과가 달랐다. 같은 빌드에서 자리만 바꿔 찍어 확인한 것이고, 왜 그런지는 확인하지 못했다. iOS 27.2 시뮬레이터에서 본 결과다. 낮에 고친 키보드 문제와 같은 종류다. 제목 표시줄에 올라가는 수식어는 스택 안쪽 맨 바깥 뷰에 건다. 필터는 어느 쪽이든 멀쩡히 돌아서, 화면을 찍기 전에는 알 수 없었다.

## 이력

- 2026-10-05 낮 — 검색 키보드가 올라와도 카드가 줄지 않게 했다.
- 2026-10-05 저녁 — 카드형에서 검색 필드를 빼고 제목 목록에만 남겼다.
