시간표 목록에서 검색 필드를 누르면 키보드만 올라오게 고쳤다. 카드는 원래 크기 그대로 있고, 아래쪽이 키보드에 가릴 뿐이다. 그리고 같은 날 저녁, 카드형에서는 검색 필드 자체를 뺐다. 그 이야기는 맨 아래 절에 있다.

## 키보드가 올라오면 화면 전체가 다시 그려졌다

목록은 시간표를 카드 한 장씩 넘겨 보는 화면이다. 카드 높이는 남는 세로 공간을 재서 정한다. 그래서 키보드가 올라와 공간이 절반이 되면 카드도 절반 높이로 다시 그려졌다. 페이지 점과 "새 시간표" 버튼도 키보드 위로 따라 올라왔다. 검색어를 치려는 순간 보고 있던 그림이 바뀌는 셈이다.

![검색 전 — 카드가 시트를 가득 채운다](/blog/timetable-list-search-keyboard/list-idle.png)

![검색 필드를 누른 뒤 — 카드 크기는 그대로, 키보드가 아래를 덮는다](/blog/timetable-list-search-keyboard/list-keyboard.png)

제목 표시줄이 접힌 만큼 카드가 위로 올라가는 것은 시스템 검색의 기본 동작이라 그대로 뒀다.

## 수식어는 있었는데 자리가 틀렸다

코드에는 `.ignoresSafeArea(.keyboard)` 가 이미 있었다. 다만 `NavigationStack` 바깥에 걸려 있었다.

```swift
NavigationStack {
    VStack { … }              // 이 내용은 여전히 키보드를 피한다
}
.ignoresSafeArea(.keyboard)   // 스택 바깥 — 안쪽에는 닿지 않는다
```

바깥에 건 수식어는 스택 컨테이너에만 적용되고, 안쪽 내용은 자기 안전 영역을 따로 받는다. 수식어를 안쪽 `VStack` 으로 옮기자 카드가 움직이지 않았다. `.navigationTitle` 이나 `.searchable` 과 같은 자리다. 이 판단의 근거는 옮기기 전과 후의 화면이고, 프레임워크 내부를 확인한 것은 아니다.

왜 아무도 몰랐나. 그 수식어가 들어간 때에는 이 화면에 글자를 칠 곳이 없었다. 키보드가 뜰 일이 없으니 효과가 있는지 볼 방법도 없었다. 검색을 넣던 날에는 결과가 제대로 걸러지는지만 찍었고, 키보드가 떠 있는 화면은 찍지 않았다.

## 제목 목록은 일부러 그대로 뒀다

목록에는 카드 대신 제목만 늘어놓는 보기도 있다. 여기서는 키보드를 계속 피하게 했다. 피하지 않으면 키보드 밑에 깔린 줄까지 스크롤할 길이 없어서, 검색 결과가 많을 때 아래쪽을 볼 수 없다. 줄은 크기가 변하지 않으니 쪼그라드는 느낌도 없다.

정리하면 기준은 하나다. 남는 공간을 재서 크기를 정하는 그림은 키보드를 무시하고, 스크롤되는 목록은 키보드를 피한다.

## 남은 것

카드형에서는 키보드가 떠 있는 동안 "새 시간표" 버튼이 가려졌다. 검색 중에 새 시간표를 만들 일은 드물다고 보고 그대로 뒀는데, 저녁에 카드형 검색이 빠지면서 이 문제도 같이 사라졌다. 그리고 화면에 입력 칸을 새로 넣을 때는 키보드가 뜬 상태를 한 장 찍는 것을 확인 절차에 넣었다.

## 2026-10-05 저녁 — 카드형에서는 검색을 뺐다

키보드를 고친 화면을 실제 기기에서 보니 다른 것이 눈에 들어왔다. 카드형 상단에 닫기, 제목, 보기 전환, 편집이 한 줄, 그 아래 검색창이 또 한 줄이다. 카드 한 장을 보러 온 화면에 머리가 두 줄이면 복잡하다.

검색 필드는 이제 제목 목록에서만 보인다. 카드형 상단은 한 줄로 돌아갔다. (이틀 뒤 뒤집혔다 — 검색 필드가 화면 아래 툴바로 내려가면서 두 보기 방식 모두에서 보이고, 카드형도 검색어로 걸러진다. 맨 아래 절.)

![카드형 — 상단이 한 줄이다](/blog/timetable-list-search-keyboard/cards-no-search.png)

![제목 목록 — 검색 필드가 제목 표시줄 바로 아래에 있다](/blog/timetable-list-search-keyboard/titles-search-top.png)

카드 넘김은 몇 장을 눈으로 훑는 화면이고, 이름으로 찾는 일은 목록 쪽에 어울린다. 카드형에서는 검색어를 무시하고, 카드형으로 돌아갈 때 검색어를 비운다. 보이지 않는 검색어가 카드를 거르면 안 되기 때문이다.

진 안은 셋이다.

- 검색을 돋보기 버튼으로 접고 보기 전환과 편집을 메뉴 하나로 묶기. 가장 많이 비지만 편집이 한 번 더 눌러야 나온다.
- 돋보기 버튼만 추가하기. 줄은 줄지만 오른쪽 버튼이 셋이 된다.
- 제목 목록에서도 접어 두고 당겨 내리면 나오게 하기. 접힌 필드는 있는 줄 모른다.

## 검색 필드가 화면 맨 아래로 갔다

제목 목록에만 달면 되니 `.searchable` 을 그 목록 뷰에 직접 걸었다. 그러자 필드가 제목 표시줄 아래가 아니라 화면 맨 아래, "새 시간표" 버튼 밑에 떴다.

![목록 뷰에 직접 걸었을 때 — 검색 필드가 맨 아래로 갔다](/blog/timetable-list-search-keyboard/titles-search-bottom.png)

```swift
// 필드가 화면 아래로 간다
case .titles: titleList.searchable(text: $query, placement: .navigationBarDrawer)

// 필드가 제목 표시줄 아래에 붙는다
VStack { … }
    .navigationTitle("시간표 목록")
    .modifier(TitleListSearch(isEnabled: style == .titles, text: $query))
```

위치를 정하는 인자는 같은데 걸린 자리에 따라 결과가 달랐다. 같은 빌드에서 자리만 바꿔 찍어 확인한 것이고, 왜 그런지는 확인하지 못했다. iOS 27.2 시뮬레이터에서 본 결과다. 낮에 고친 키보드 문제와 같은 종류다. 제목 표시줄에 올라가는 수식어는 스택 안쪽 맨 바깥 뷰에 건다. 다만 이것만으로는 모자랐다. 이틀 뒤 같은 증상이 다른 길로 돌아왔고, 아래 절에 적었다. 필터는 어느 쪽이든 멀쩡히 돌아서, 화면을 찍기 전에는 알 수 없었다.

## 2026-10-07 — 맨 바깥에 걸어도, 늦게 달면 또 아래로 갔다

이틀 뒤 제보가 왔다. 검색창이 "새 시간표" 버튼 밑에 뜰 때가 있다. 위 그림과 똑같은 모양이다. 수식어는 고친 자리에 그대로 있었다.

"뜰 때가 있다" 는 말이 단서였다. 시트를 여는 길을 나눠 검색 필드의 y 좌표를 쟀다.

| 길 | 검색 필드 y | 새 시간표 버튼 y |
|---|---|---|
| 카드형으로 연 시트에서 제목 목록으로 전환 | 808 | 727 |
| 그 상태에서 편집 모드 왕복, 새 시간표 시트 왕복 | 808 | 727 |
| 제목 목록으로 연 시트 | 132 | 779 |
| 그 뒤 카드형과 제목 목록을 오가기 | 132 | 779 |

자리는 `NavigationStack` 이 처음 만들어질 때 `.searchable` 이 달려 있었느냐로 정해졌다. 그리고 한 번 정해지면 바뀌지 않았다. 카드형으로 열린 스택에는 검색이 없다. 보기 방식을 바꾸면 그제야 달리는데, 이때는 `placement` 가 무시된다. 보기 방식은 기기에 저장되므로 마지막에 카드형으로 닫은 사람만 이 길을 밟는다.

고친 것은 한 줄이다. 보기 방식이 바뀌면 스택을 새로 만든다.

```swift
NavigationStack {
    VStack { … }
        .modifier(TitleListSearch(isEnabled: style == .titles, text: $query))
}
.id(style)   // 어느 쪽으로 가든 "그 방식으로 처음 열린 스택" 이 된다
```

고친 뒤에는 표의 모든 길에서 132 다. 스택이 새로 만들어지면 그 안의 `.task` 도 다시 돈다. 처음 한 번만 해야 하는 일, 여기서는 열려 있는 시간표로 스크롤 자리를 잡는 일은 스택 바깥으로 옮겼다. 검색어와 편집 모드 같은 상태는 원래 스택 바깥에 있어서 그대로 남는다.

진 안은 둘이다.

- 검색 필드를 직접 그리기. 자리는 확실하지만 시스템 필드의 모양, 취소 버튼, 키보드 동작을 다시 만들어야 한다.
- `.searchable` 을 늘 달아 두기. 카드형 상단에 검색 줄이 돌아온다. 이틀 전에 뺀 것이다.

왜 두 번 놓쳤나. 첫 수정을 확인한 화면은 제목 목록으로 연 시트 한 장이었다. 이번에도 고친 뒤 첫 확인이 헛돌았다. 앞선 실행이 보기 방식을 제목 목록으로 남겨서, 다음 실행은 문제의 길을 밟지 않고 전부 통과했다. 저장되는 설정이 있는 화면은 확인 절차가 그 설정을 시작 상태로 되돌리고 화면을 다시 연 뒤에 재야 한다. 그리고 들어오는 길마다 따로 잰다.

왜 그런지는 이번에도 확인하지 못했다. iOS 27.2 시뮬레이터에서 잰 결과이고, 시간표가 많을 때 전환 뒤 스크롤 자리가 이어지는지는 아직 찍지 않았다.

## 2026-10-08 — 검색 필드가 화면 아래로 내려가자, 검색하는 동안 복제·삭제가 사라졌다

그 사이 검색 필드는 화면 아래 시스템 툴바로 내려갔다. 평소엔 검색 · 가져오기 · 새 시간표, 편집 모드엔 복제 · 검색 · 삭제가 한 줄에 선다. 카드형 상단이 두 줄이던 문제는 이걸로 끝났고, 카드형도 검색어로 걸러진다. 이틀 전에 "카드형은 검색어를 무시한다" 고 적은 규칙은 이때 뒤집혔다.

그런데 편집 모드에서 검색을 하면 결과를 골라도 할 수 있는 게 없었다. 검색 필드를 누르는 순간 양옆의 복제·삭제 버튼이 사라지고, 글자를 쳐서 한 줄로 걸러 그 줄을 체크해도 버튼은 돌아오지 않는다. 키보드의 검색 키를 눌러도 그대로다. 남은 건 검색 필드 옆 X 하나인데, 그걸 누르면 검색어가 지워져 걸러진 결과도 같이 사라진다.

![검색 키로 제출한 뒤 — 줄은 체크됐는데 하단엔 검색 필드와 X 뿐이다](/blog/timetable-list-search-edit-actions/search-submitted-buttons-gone.png)

시스템 하단 툴바의 검색 필드는 펼쳐져 있는 동안 같은 줄의 다른 버튼을 전부 접는다. 접근성 트리에서도 사라진다. 키보드의 검색 키는 키보드만 내리고 펼침은 유지한다. 펼침을 끝내는 건 X 뿐이고, X 는 UIKit 의 검색 취소와 같아서 검색어까지 비운다. 내비게이션 바를 남기라는 `.searchPresentationToolbarBehavior(.avoidHidingContent)` 는 이미 걸려 있었지만 이름 그대로 위쪽 바 이야기라 하단 줄엔 관여하지 않았다.

고친 건 펼침을 우리가 끝내는 것이다. `.searchable(text:isPresented:)` 로 펼쳐진 상태를 잡고, 검색 키 제출 · 편집 모드에서 줄을 탭해 고르기 · 카드를 탭하기 · 보기 방식 전환에서 내린다. 검색어는 건드리지 않는다. 걸러진 목록도 그대로이고 접혔던 버튼만 돌아온다.

![줄을 탭한 뒤 — 검색어 "리아" 가 남은 채 복제·삭제가 돌아왔다](/blog/timetable-list-search-edit-actions/row-picked-buttons-back.png)

여기서 하나 더 걸렸다. 프로그램으로 내리면 접힌 필드가 검색어 대신 플레이스홀더 "검색" 을 그렸다. 바인딩의 검색어는 그대로라 목록은 한 줄로 걸러진 채인데, 필드만 비어 보이니 "검색어가 없는데 왜 하나만 보이지" 가 된다. 보기 방식을 바꿔 스택을 새로 만들면 제대로 그리는 걸로 봐서 표시만 어긋난 것이다. 펼침이 내려갈 때 검색어 뒤에 공백 하나를 붙였다가 다음 런루프에 떼는 걸로 필드가 바인딩을 다시 읽게 했다. 필터가 앞뒤 공백을 자르니 그 사이 목록은 깜빡이지 않는다.

왜 못 봤나. 하단 줄을 시스템 툴바로 옮기던 날 "검색 중에는 버튼이 접힌다, 시스템이 해 준다" 까지 보고, 그 버튼이 **언제 돌아오는지**는 안 봤다. 그날 캡처는 포커스 · 입력 · 제출 순간까지였다. 검색 결과를 골라 복제하거나 지우는 경로는 검색 필드와 버튼이 같은 줄에 선 뒤에야 생긴 것이라, 검색이 위에 있던 때의 확인 목록엔 없었다. 이제 검색 UI 를 만지면 "제출 뒤" 와 "결과를 탭한 뒤" 의 하단 줄까지 찍는다.

iOS 27.2 시뮬레이터에서 잰 결과다. 아이패드 창에서는 아직 찍지 않았다.

## 이력

- 2026-10-05 낮 — 검색 키보드가 올라와도 카드가 줄지 않게 했다.
- 2026-10-05 저녁 — 카드형에서 검색 필드를 빼고 제목 목록에만 남겼다.
- 2026-10-07 — 카드형으로 연 시트에서 전환하면 검색 필드가 아래로 가던 것을 고쳤다.
- 2026-10-08 — 하단 툴바로 간 검색 필드가 펼쳐진 동안 복제·삭제를 접던 것을, 제출·고르기에서 펼침을 내려 풀었다.
