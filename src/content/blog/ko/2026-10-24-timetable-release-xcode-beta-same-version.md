1.2.1 을 심사에 넣으려고 버튼을 눌렀는데 App Store Connect 가 거절했다. "This build is using a beta version of Xcode and can't be submitted." 그날 올린 빌드 329, 330, 331 이 전부 그랬다. 배포 레인은 하루 전에 "출시는 Xcode 27.1 로 만든다" 는 규칙을 막 얻은 상태였고, 그 규칙은 지켜지고 있었다. 27.1 이 둘이었을 뿐이다.

## 하루 전, 출시 빌드가 옛 SDK 로 나가고 있었다

이야기는 전날 시작한다. iPhone Duo 대응을 끝내고 시뮬레이터에서 접힘·펼침을 다 확인했는데, 실제로 나간 TestFlight 빌드에서는 Duo 가 작은 호환 레이아웃으로 떴다. 아카이브의 `DTSDKName` 을 보니 `iphoneos26.2` 였다. 시뮬레이터 확인은 Xcode 27.1 로 했고, fastlane 레인은 `xcode-select` 가 가리키는 Xcode 로 아카이브했다. 이 기계의 `xcode-select -p` 는 26.3 이었다.

Duo 는 바이너리의 `LC_BUILD_VERSION sdk` 가 27.1 이상일 때만 제 크기 레이아웃과 세로 툴바를 준다. 그래서 레인에 두 가지를 넣었다. 아카이브 전에 `CFBundleShortVersionString` 이 `27.1` 인 Xcode 를 찾아 그 레인만 `DEVELOPER_DIR` 을 바꾸고, 아카이브 뒤에 `otool -l` 로 SDK 를 읽어 27.1 아래면 업로드 전에 멈춘다. 주석에는 "베타(27.2 등)는 App Store 에 못 올리니 버전을 정확히 맞춘다" 고 적었다. 그 문장이 다음 날의 구멍이었다.

## 같은 "27.1" 이 둘 있었다

이 기계에는 Xcode 가 다섯 개 깔려 있다. 이름은 `Xcode.app`, `Xcode 2.app`, `Xcode 3.app`, `Xcode-beta.app` 식이라 이름으로는 아무것도 알 수 없다. 그중 `Xcode 3.app` 이 27.1 이었고, 레인은 그걸 골랐다.

| | 27.1 beta | 27.1 정식 |
|---|---|---|
| `CFBundleShortVersionString` | 27.1 | 27.1 |
| `xcodebuild -version` 첫 줄 | Xcode 27.1 | Xcode 27.1 |
| SDK | 27.1 | 27.1 |
| `ProductBuildVersion` | 27A9269 | 27A9275 |
| 공개일 | 9월 18일 | 10월 15일 |

베타와 정식을 가르는 값은 `Contents/version.plist` 의 `ProductBuildVersion` 하나다. 버전 문자열도, `xcodebuild -version` 도, SDK 하한 검사도 둘을 구별하지 못한다. 베타 빌드 번호에 소문자가 붙는다는 짐작도 틀렸다. 27.2 베타는 `27B5028f` 지만 27.1 베타는 `27A9269` 다. 어느 번호가 정식인지는 로컬에 표식이 없고, Apple 의 릴리스 피드가 유일한 근거다.

전날의 규칙은 "다음 버전의 베타" 만 생각했다. 같은 버전의 베타가 정식보다 먼저 깔려 있다가 정식이 나온 뒤에도 그 자리에 남아 있는 경우를 보지 않았다. 심사 제출 버튼이 유일한 검사였고, 그 검사는 세 빌드를 올린 뒤에야 돌았다.

## 정식 빌드 번호를 상수로 박고, 아카이브에서 되읽는다

레인에 `RELEASE_XCODE_BUILD = "27A9275"` 를 두고 후보 Xcode 중 `ProductBuildVersion` 이 이 값인 것만 고르게 했다. 같은 버전 문자열의 Xcode 가 있어도 빌드가 다르면 경로와 번호를 나열하며 멈춘다. 경로를 강제하는 환경 변수도 같은 검사를 받는다. 강제 경로가 베타를 밀어 넣는 뒷문이 되면 안 되기 때문이다.

아카이브 뒤 검사도 늘렸다. 심사가 보는 값은 아카이브된 앱 Info.plist 의 `DTXcodeBuild` 이니, SDK 하한과 함께 그 값이 정식 번호와 같은지 비교한다. 어느 경로로 아카이브됐든 업로드 전에 걸린다.

버린 대안은 둘이다. 릴리스 피드를 레인에서 실시간으로 읽는 것은 네트워크와 파싱에 배포가 묶인다. `Xcode 3.app` 을 지우기만 하는 것은 다음 베타가 깔리는 날 재발한다. 정식 번호는 사람이 피드에서 읽어 상수로 박고, 새 정식이 나오면 그 상수를 올리는 PR 을 낸다. Xcode 를 받는 것만으로 레인이 바뀌지 않는 것은 의도다.

## 지금

정식 27.1 로 다시 아카이브한 빌드 332 가 1.2.1 에 붙어 있다. `DTXcodeBuild` 는 `27A9275`, SDK 는 27.1 이다. 배포 전에 깔린 Xcode 전부의 빌드 번호를 나열하고 피드와 맞춰 보는 절차는 배포 스킬에도 들어갔다.
