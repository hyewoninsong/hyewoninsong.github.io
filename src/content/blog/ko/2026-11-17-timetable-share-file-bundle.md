시간표 앱의 캘린더를 이제 파일로 보낼 수 있다. 캘린더 `…` › 공유 › 파일로 내보내기를 누르면 캘린더 전체가 `.supertimetable` 파일 하나로 나가고, 받은 사람이 파일을 열면 자기 캘린더로 들어와 바로 열린다.

## 같은 파일, 안이 바뀌었다

예전 `.supertimetable` 은 시간표 하나를 그대로 적은 JSON 이었다. 이제는 zip 이다. 안에는 목차 한 장과 문서가 들어 있다.

| 안의 파일 | 내용 |
|---|---|
| `manifest.json` | 이 파일의 형식 이름 · 판 번호 · 문서 목록(종류와 위치, 순서대로) |
| `timetables/<id>.json` | 시간표 하나 — 예전 공유 파일과 똑같은 JSON |
| `calendars/<id>.json` | 캘린더 하나 — 앱이 기기에 저장하는 캘린더와 똑같은 JSON |

확장자도, 파일을 눌렀을 때 앱이 뜨는 방식도 그대로다. 앱은 파일의 첫 네 바이트를 보고 zip 이면 새 형식으로, 아니면 예전 JSON 으로 읽는다. 그래서 예전에 받아 둔 시간표 파일은 지금도 열린다.

그동안 캘린더에도 "파일로 내보내기" 메뉴가 있긴 했다. 눌러 보면 지금 보고 있는 **한 주**를 시간표 파일로 내보내고 있었다. 반복 일정의 나머지 주, 따로 옮겨 둔 회차, 날짜 메모는 다 빠졌다. 이제는 캘린더 문서 전체가 나간다.

## JSON 에 종류 표시만 더하면 안 됐다

처음 떠올린 건 가장 작은 변경이었다. 캘린더 JSON 맨 위에 `"type": "calendar"` 를 하나 더해 같은 확장자로 내보내는 것이다. 이 길이 진 이유는 이틀 전의 다른 결정에 있다. 캘린더 저장 키를 시간표와 같은 이름으로 맞춰 두었다 — `schedules`, `startDayOfWeek` 처럼. 그래서 `type` 을 모르는 옛 앱이나 Android 앱이 이 파일을 열면 거절하지 않는다. **이상한 시간표 하나로 받아들인다.** 반복 규칙은 사라지고 일정은 엉뚱한 요일에 앉는다. 조용히 엉뚱하게 읽히는 쪽이 "열 수 없음" 보다 나쁘다.

다른 두 안도 견줬다.

- **JSON 봉투 하나** (`{"documents": [...]}`) — 옛 앱이 시간표 이름 키를 못 찾아 거절하는 건 zip 과 같다. 하지만 시리즈 수 상한을 없앤 캘린더는 커질 수 있다. 통째로 읽어야 하고, 문서 하나씩 크기 상한을 걸기도 어렵다.
- **캘린더 전용 확장자** (`.supercalendar`) — 파일 종류를 하나 더 등록해야 하고, Android 쪽 "연결 프로그램" 필터도 한 벌 더 깔아야 한다. 그 필터는 이미 기기마다 따로 맞추느라 몇 번을 고친 자리다.

zip 은 옛 앱이 "이 파일을 열 수 없음" 으로 깨끗하게 거절한다. 시간표와 캘린더를 한 파일에 같이 담을 수 있고, 안의 내용은 예전 JSON 그대로라 디코더도, 깨진 파일을 거절하는 규칙도 새로 만들지 않았다. 바뀐 건 껍데기뿐이다.

## 남이 보낸 zip 을 믿지 않는 법

받은 파일은 남이 만든 것이다. 그래서 읽는 순서를 정했다.

1. zip 끝의 목록(중앙 디렉터리)만 먼저 읽는다. 파일은 64MB, 항목은 64개, 항목 하나는 32MB 까지다. 넘으면 **풀기 전에** 거절한다.
2. 풀고 나서 실제 크기가 목록에 적힌 크기와 다르면 거절한다. 작게 적어 놓고 크게 풀리는 파일이 여기서 걸린다. CRC 도 대조한다.
3. 문서 하나라도 일부가 깨져 있으면 묶음 전체를 거절한다. 일부만 들어오면 받은 사람은 무엇이 빠졌는지 모른다.
4. 시간표 20개, 캘린더 20개 상한에 다 못 들어가면 하나도 넣지 않는다.

zip 은 외부 라이브러리 없이 직접 짰다. 쓰기는 압축 없이(stored) 고정 시각으로 해서 같은 내용이면 같은 바이트가 나온다. 읽기는 Android `ZipOutputStream` 이 쓰는 deflate 도 받는다. 풀기는 시스템 `Compression` 프레임워크가 한다.

## 대가와 지금 상태

**옛 버전 앱은 새 파일을 못 연다.** 받는 쪽이 업데이트해야 한다. 시간표 공유까지 지금 바꿀지, 캘린더만 새 형식으로 낼지 골라야 했는데, 형식이 두 갈래로 오래 남는 쪽을 피했다. 그래서 Android 도 같은 날 같은 형식으로 바꿨다. Android 에는 아직 캘린더가 없어서 묶음의 시간표만 들이고, 캘린더만 든 파일에는 "이 버전에서 열 수 없는 캘린더" 라고 따로 알린다.

같은 날 캘린더 하나의 일정 시리즈 500개 상한도 없앴다. 저장소를 SQLite 로 옮겨 편집 하나가 바뀐 줄 하나만 쓰게 된 뒤라 가능했다. 캘린더는 시간이 갈수록 쌓이는 문서라 500 은 몇 년 쓰면 닿는 벽이었다. 실기기 AirDrop 과 Mac 에서 주고받기는 아직 해 보지 않았다.
