SuperTimetable 에 애플워치 앱과 컴플리케이션을 넣었다. 타깃 넷이 전부 빌드되고, 워치 앱이 아이폰 앱 안에 제대로 들어가는 것까지 확인하고 합쳤다. 그다음 날 테스트 빌드를 올리려는데 배포가 네 번 멈췄다. 한 군데를 풀면 다음 자리에서 멈췄고, 넷 다 "빌드된다" 로는 볼 수 없는 자리였다.

## 막힌 자리는 전부 빌드 바깥에 있었다

| 순서 | 어디서 | 무엇이 없었나 |
|---|---|---|
| 1 | 배포 전 점검 | 워치 앱 식별자에 App Group 이 없다 |
| 2 | 아카이브 서명 | 워치 타깃이 쓸 프로비저닝 프로파일이 없다 |
| 3 | 아카이브 서명 | 아이폰 앱 식별자에 iCloud 컨테이너가 안 붙어 있다 |
| 4 | 업로드 | 워치 앱에 아이콘이 없다 |

시뮬레이터 빌드는 서명을 하지 않고, 스토어 검증도 거치지 않는다. 그래서 넷 중 어느 것도 합치기 전에는 보이지 않았다.

## 받아 둔 프로파일을 아카이브는 쓰지 않았다

두 번째가 가장 헷갈렸다. 에러는 이랬다.

```
Provisioning profile "iOS Team Provisioning Profile: *" doesn't include the App Groups capability.
(in target 'TimetableWatch')
```

프로파일 이름 끝의 `*` 는 팀 와일드카드라는 뜻이다. 보통은 "그 식별자가 등록돼 있지 않다" 는 신호인데, 식별자는 이미 등록돼 있었다. 배포 스크립트는 타깃마다 `sigh` 로 App Store 프로파일을 받아 오고 있었고, 그 안에는 워치용 App Group 도 들어 있었다.

문제는 아카이브가 그 프로파일을 쓰지 않는다는 데 있었다. 프로젝트가 자동 서명이라, 아카이브 단계의 `xcodebuild` 는 Xcode 가 관리하는 개발 프로파일을 스스로 고른다. 기존 타깃은 예전에 받아 둔 프로파일이 맥에 남아 있어서 지나갔다. 새 타깃만 받아 둔 것이 없어서 와일드카드로 떨어졌고, 와일드카드 프로파일은 App Group 을 담지 못한다.

`-allowProvisioningUpdates` 는 이미 붙어 있었는데 내보내기 단계에만 있었다. 내보내기는 아카이브가 끝난 뒤다. 아카이브 쪽에도 넘기자 풀렸다. 단, 이 플래그는 Xcode 에 그 팀의 계정이 로그인돼 있어야 동작한다. 맥에는 개인 팀 계정 하나만 있었고, 새 프로파일을 만들 일이 없는 동안은 아무도 몰랐다.

API 키를 직접 넘기는 방법도 시도했다. `sigh` 는 받아 주는 같은 키를 `xcodebuild` 는 인증 실패로 돌려보냈다. 이유는 끝내 확인하지 못했다.

## 기능이 켜진 것과 붙은 것은 다른 일이다

세 번째는 iCloud 였다. 개발자 포털에서 iCloud 기능은 켜져 있었다. 그런데 컨테이너를 만들고 그 식별자에 붙이는 것은 별개의 단계이고, 그게 빠져 있었다. 기능 목록만 봐서는 구분이 안 된다. 받아 온 프로파일을 열어 보면 보인다.

```
icloud-container-identifiers  []
```

빈 배열이면 붙지 않은 것이다. App Group 도 같은 식으로 확인했다. 컨테이너와 그룹을 만들고 붙이는 일은 공개 API 가 없어서 사람이 포털에서 해야 한다.

## 워치 앱은 아이콘도 따로 가진다

서명이 풀리자 아카이브와 내보내기가 통과했고, 업로드에서 거절됐다.

```
409 Missing Icons. No icons found for watch application 'Timetable.app/Watch/TimetableWatch.app'
```

워치 앱은 아이폰 앱 안에 들어가지만 독립된 번들이다. 제 `Info.plist` 에 `CFBundleIconName` 이 있어야 한다. 아이콘이 없어도 컴파일, 서명, 임베드는 전부 통과한다. 스토어 검증만 거절하고, 그건 아카이브를 끝까지 돌린 뒤에야 온다.

아이폰 앱의 아이콘 파일은 이미 워치용 원형을 지원한다고 선언하고 있었다. 그림은 그대로 두고, 워치 타깃에 같은 아이콘을 넣고 빌드 설정에서 이름을 지정했다. 두 타깃이 파일 하나를 공유하게 하는 방법도 있었지만, 프로젝트가 폴더 단위로 타깃을 나누는 구조라 사본을 두고 "둘이 같은가" 를 테스트로 묶는 쪽이 덜 위험했다.

서명 없이 워치 앱만 빌드해서 확인하는 데는 1분이면 된다.

```bash
xcodebuild -target TimetableWatch -sdk watchos -configuration Release CODE_SIGNING_ALLOWED=NO build
plutil -p .../TimetableWatch.app/Info.plist | grep CFBundleIconName
```

## 타깃 추가의 끝은 업로드다

지금은 워치 앱이 들어간 빌드가 TestFlight 에 올라가 있다. 새 번들 식별자가 생길 때마다 세 가지를 센다. 포털에 그룹과 컨테이너가 붙어 있는가, 아카이브가 프로파일을 구할 수 있는가, 번들마다 아이콘이 있는가. 셋 다 빌드 로그에는 나오지 않는다.
