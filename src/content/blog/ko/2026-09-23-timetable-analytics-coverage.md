SuperTimetable 은 이벤트 31개를 보내고, 그 매개변수는 오전에 전부 GA4 맞춤 측정기준으로 등록해 뒀다. 그래서 "통계를 볼 수 있게 보완할 게 있나" 라는 질문에 처음엔 없다고 답할 뻔했다. 보내는 것은 전부 읽히는 형태였다. 문제는 **보내지 않는 것**이었다.

## 열거형이 아니라 기능 목록으로 센다

이벤트 열거형은 누군가 언젠가 세기로 한 것의 목록이다. 세기로 하지 않은 것은 거기 없다. 그래서 감사는 열거형이 아니라 앱의 기능 목록을 놓고 했다 — 시트마다, 권한 프롬프트마다, 내보내기 경로마다, 실패 알럿마다 진입점에서 `logEvent` 호출을 세는 식으로.

| 기능 | 이벤트 | 답할 수 없던 질문 |
|---|---|---|
| 첫 실행 튜토리얼 | 0 | 어느 스텝에서 사람들이 그만두나 |
| 인쇄 (용지·N-up·흑백 옵션이 있는 모듈 전체) | 0 | 쓰긴 하나, 벡터 인쇄가 조용히 비트맵으로 떨어지는 빈도 |
| 알람 권한 프롬프트 | 0 | 알람 기능의 첫 관문에서 몇 %가 막히나 |
| 실패 경로 | 앱 전체에 `error_occurred` 호출 **한 곳** | 가져오기 시도 중 몇 %가 실패하나 |
| 사용자 속성 | `setUserProperty` 호출 0 | 시간표를 많이 만든 사람과 하나만 만든 사람의 리텐션 차이 |

튜토리얼은 앱을 처음 여는 사람이 보내는 첫 90초다. 거기서 아무것도 세지 않고 있었다.

## 퍼널은 이벤트 네 개가 한 세트다

튜토리얼에 붙인 이벤트는 `tutorial_begin` → `tutorial_step_reached` → `tutorial_complete`, 그리고 `tutorial_skipped`. 앞의 둘은 GA4 가 권장 이벤트로 이름을 정해 둔 것이라 그대로 썼다 — 콘솔이 기본 보고서로 묶어 준다.

핵심은 `tutorial_step` 매개변수 하나를 **도달**과 **이탈** 두 이벤트가 같은 어휘로 공유한다는 점이다. 측정기준 한 열에서 "어디까지 왔고 어디서 나갔나" 를 읽으려면 그래야 한다. 이름을 `reached_step` / `skipped_step` 으로 가르면 보고서에서 두 열을 매번 맞춰 봐야 한다. 매개변수 이름을 이벤트끼리 공유하지 않는다는 규칙을 계약 테스트가 지키고 있어서, 이 하나만 의도적 공유 목록에 올렸다.

찍는 자리는 뷰가 아니라 상태 기계다. 스텝 전이는 전부 `TutorialState` 안에서 일어나고, 창 폭이 바뀌어 코스가 갈리면서 스텝을 자동으로 건너뛰는 전이는 뷰가 모른다. 거기서 찍어야 빠지는 게 없다. `tutorial_begin` 은 웰컴 카드가 뜬 시점이 아니라 "시작" 을 누른 시점이다 — 카드 노출은 사용자가 한 일이 아니다.

## Crashlytics 는 원인이고, 애널리틱스는 비율이다

가져오기 실패는 이미 Crashlytics non-fatal 로 가고 있었다. 어떤 파일이 왜 깨졌는지는 거기서 다 보인다. 그런데 "가져오기 시도 중 몇 %가 실패하나" 는 거기서 못 센다 — 성공이 Crashlytics 에 안 가기 때문이다. 그래서 실패 분기마다 `error_occurred` 도 같이 찍었다. 이미지 내보내기의 렌더 실패와 쓰기 실패, 파일 공유의 인코딩 실패, 가져오기의 읽기 실패와 디코딩 실패, 인쇄의 PDF 폴백. 값은 메시지가 아니라 `render_failed` 같은 고정 낱말이다.

알람 권한은 프롬프트 상태를 아는 층에서만 찍을 수 있다. 호출부는 Bool 하나를 받을 뿐이라 "처음 물어서 허용" 과 "이미 거부된 채로 켜려 함" 을 못 가른다. 후자를 `already_denied` 로 따로 세는 이유는, 그 숫자가 기능 수요이면서 동시에 설정 하나에 막힌 사람의 수이기 때문이다.

## 사용자 속성은 버킷으로

`timetable_bucket`(0 / 1 / 2-3 / 4-9 / 10+), `schedule_bucket`(0 / 1-9 / 10-29 / 30-79 / 80+), `alarm_user`(true / false). 원값을 그대로 보내면 값 종류가 무한이라 측정기준으로 못 쓴다. 이 셋은 이벤트가 아니라 사용자에 붙어서 **모든 보고서**를 "어떤 사용자인가" 로 쪼갠다. 런치와 백그라운드 진입 시 동기화하고, 라벨은 테스트가 못박았다 — 등록된 어휘를 바꾸면 옛 값과 새 값이 한 열에 섞인다.

## 지금 상태

새 매개변수 10개와 사용자 범위 3개를 등록하고 되읽어 확인했다. 등록 스펙은 저장소에 두어서, 다음에 이벤트를 추가하는 사람이 코드와 같은 PR 에서 등록까지 하게 했다. 등록은 소급되지 않으니 "나중에" 는 그만큼의 구멍이다. 보고서에 뜨는 데는 하루이틀 걸린다.
