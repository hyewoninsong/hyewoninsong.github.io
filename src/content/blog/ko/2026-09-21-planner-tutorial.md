하루 플래너를 처음 켜면 이제 날짜 바 아래에 작은 카드가 내려온다. "시작" 을 누르면 카드가 "빈 곳을 길게 누른 뒤 아래로 끌어 보세요" 로 바뀌고, 그 아래 타임라인에서 손가락 하나가 빈 자리를 길게 누르고 아래로 끌어 점선 블록을 만드는 동작을 반복한다. 사용자가 진짜로 그렇게 해서 블록을 하나 놓으면 카드가 다음 단계로 넘어간다. 이 앱은 배치하는 길이 빈 곳 롱프레스 드래그 하나뿐이고 블록 액션은 선택한 블록을 다시 탭해야 나오는 메뉴에 있어서, 화면 어디에도 "여기 누르세요" 버튼이 없다. 그래서 처음 켠 사람은 "어떻게 넣지" 에서 막혔다.

![웰컴 카드. 날짜 바 아래에 떠 있고 타임라인은 그대로 살아 있다](/blog/planner-tutorial/welcome-card.png)

## 넘어가는 조건은 전부 실제 동작

처음 넣었을 때의 여섯 단계다. 지금은 여덟 단계로 바뀌었다(맨 아래 9월 27일 절).

| 단계 | 카드가 시키는 것 | 넘어가는 조건 |
|---|---|---|
| 1 배치하기 | 빈 곳을 길게 누르고 아래로 끌어 할일 고르기 | 할일 선택 시트에서 골라 블록이 놓임 |
| 2 옮기기 | 블록을 길게 누르고 위아래로 끌기 | 드래그로 시작 시각이 바뀜 |
| 3 길이 조절 | 선택된 블록의 아래 가장자리 끌기 | 길이가 바뀜 |
| 4 완료 표시 | 블록 왼쪽 동그라미 탭 | 완료가 됨 |
| 5 블록 메뉴 | 선택된 블록을 한 번 더 탭 | 컨텍스트 메뉴가 열림 |
| 6 되돌리기 | 왼쪽 아래 실행 취소 | 실행 취소가 눌림 |

"다음" 버튼이 없다. 단계마다 앱 안의 실제 동작 자리(배치 시트가 닫히는 곳, 드래그를 놓는 곳, 체크박스, 메뉴가 열리는 곳, 실행 취소 버튼)가 "이 일이 일어났다" 고 튜토리얼에 알리고, 튜토리얼은 지금 기다리던 일일 때만 넘어간다. 옮기기 단계에서 실수로 체크박스를 눌러도 아무 일도 안 일어난다. 드래그를 했다가 제자리에 놓은 것도 동작으로 치지 않는다.

![배치 단계. 카드 아래 타임라인에서 손가락이 12시 자리를 길게 누르고 아래로 끌어 점선 블록을 키우고 있다](/blog/planner-tutorial/place-demo.png)

손가락 데모는 진짜 타임라인 위에 그린다. 화면 좌표에 띄운 오버레이가 아니라 스크롤되는 콘텐츠 안에 넣어서, 사용자가 스크롤하면 같이 따라간다. 어디서 보여 줄지는 그때그때 실제 데이터에서 계산한다. 배치 데모는 지금 보이는 구간의 위쪽 3분의 1 근처에서 비어 있는 30분 격자를 찾아 거기서 한 시간짜리를 끈다(아래로 끄는 동작이 화면 안에 머물도록 위쪽에서 시작한다). 옮기기는 선택된 블록에서 한 시간 뒤가 비어 있으면 거기로, 아니면 한 시간 앞, 그다음 두 시간. 길이 조절은 아래가 비어 있으면 늘리고 막혀 있으면 줄인다. 대상이 화면 밖이면 단계마다 한 번 스크롤해서 보여 준다.

![완료 단계. 블록 왼쪽 체크 밴드에 테두리가 숨 쉬듯 깜빡이고 손가락이 그 위를 탭한다](/blog/planner-tutorial/complete-demo.png)

## 캐러셀도 덮개도 아닌 이유

시간표 앱에 이미 있던 튜토리얼을 옮겨 온 것이라 형태는 정해져 있었지만, 옮기면서 왜 이 형태인지 다시 따져 봤다.

그림 몇 장 넘기는 온보딩이 제일 싸다. 그런데 이 앱의 두 핵심 동작은 읽어서 익혀지지 않는다. "0.2초 길게 누른 뒤 끌기" 와 "선택된 것을 한 번 더 탭하면 메뉴" 는 손으로 한 번 해 봐야 몸에 남는다. 그래서 따라하기다.

화면을 어둡게 하고 대상만 구멍을 뚫는 spotlight 는 "여기" 가 분명하다. 하지만 그 상태로 실제 제스처를 시키려면 구멍 안팎의 터치를 따로 다뤄야 하고, 이 앱은 세로 스크롤 안에 가로 페이징이 있어서 덮개가 그 둘과 싸운다. 그래서 덮개 없이 카드만 띄우고, "여기" 는 데모 레이어가 실제 대상 위에 그리는 펄스 테두리로 가리킨다. 타임라인은 튜토리얼 내내 완전히 살아 있다.

대신 단계와 무관한 컨트롤은 잠근다. 날짜 이동, 설정, 프로필, 서랍, 실행 취소와 다시 실행. 배치 단계에서 실행 취소를 누르면 다음 단계가 가리킬 블록이 사라지기 때문이다. (처음엔 실행 취소가 마지막 단계에서 풀렸는데, 되돌리기 단계가 빠지면서 끝까지 잠긴다.) 타임라인 제스처만은 잠그지 않는다. 블록을 메뉴에서 지워 버렸다면 사용자가 스스로 하나 다시 놓아서 이어 갈 수 있어야 한다.

## 옮기면서 달라진 것

시간표 앱은 아홉 단계였다. 복제, 삭제, 격자 잠금은 이 앱에 없어서 뺐고, 이 앱만의 두 길인 왼쪽 체크박스와 재탭 메뉴를 넣었다. 삭제는 메뉴 안에 있으니 "메뉴 열기" 로 갈음했다.

카드 자리도 다르다. 시간표는 격자 맨 위였는데 여기서 화면 맨 위는 날짜 바다. 날짜 바를 덮으면 잠가 둔 컨트롤을 카드가 가리는 꼴이라, 날짜 바 아래 타임라인 위에 얹어서 날짜 바가 흐려진 채로 보이게 했다.

데모의 "다시 계획" 자리도 한 번 헛디뎠다. 시간표 앱은 반복 루프 안에서 매 사이클 현재 데이터로 다시 계획하는데, SwiftUI 의 `task` 클로저는 시작 시점의 값을 잡고 있어서 그 안에서 새 데이터를 읽으면 옛 값이 나온다. 배치·선택·(배치 단계에서만) 스크롤 위치를 `task(id:)` 의 키로 넣어, 바뀌면 루프를 새로 돌게 했다.

## 남은 것

튜토리얼은 설정의 도움말에서 언제든 다시 볼 수 있다. 새 동작이 생겨도 튜토리얼에 저절로 들어가지는 않는다. 단계를 더하려면 이벤트 하나, 데모 장면 하나, 여덟 언어 문구를 같이 넣어야 한다.

## 2026-09-27 — 블록 하나 만지는 법에서, 처음 쓰는 하루로

여섯 단계를 다시 해 보니 블록 **하나**를 만지는 법만 가르치고 있었다. 이 앱이 다른 플래너와 갈리는 건 블록 여럿을 이어 두고 한 번에 옮기는 묶기인데 튜토리얼에 없었고, 첫 단계는 "할일을 골라 보세요" 였지만 처음 켠 사람에겐 고를 할일이 없다. 할일 목록에서 기록을 보고 다 쓴 할일을 치우는 길도 안 나왔다. 그래서 순서를 처음 쓰는 하루 그대로 다시 짰다.

| 단계 | 넘어가는 조건 |
|---|---|
| 1 잠금 풀기 | 왼쪽 아래 자물쇠를 누름 |
| 2 할일 만들어 배치하기 | 빈 곳을 끌어 연 시트에서 새 할일을 만들어 놓음 |
| 3 하나 더 배치하기 | 한 번 더 놓음 |
| 4 묶기 | 블록을 고르고 다른 블록의 연결 버튼을 눌러 이음 |
| 5 같이 옮기기 | 묶음을 끌어 실제로 옮김 |
| 6 메모 달기 | 메모를 적어 **저장**함 — 입력창을 여는 것만으로는 안 넘어간다 |
| 7 기록 보기 | 할일 목록에서 할일을 눌러 기록 화면이 뜸 |
| 8 보관하기 | 그 할일을 보관함 |

길이 조절과 완료 표시는 뺐다. 손잡이와 동그라미는 모양이 제 할 일을 말한다. 되돌리기도 뺐다 — 실행 취소는 튜토리얼 내내 잠겨 있고, 누르는 순간 다음 단계가 가리킬 블록이나 이어 둔 줄이 사라진다.

묶기 데모는 두 번 움직인다. 아무것도 안 골랐으면 손가락이 블록 하나를 탭해 고르고, 고른 뒤에는 가장 가까운 안 이은 블록의 제목 줄 오른쪽 연결 버튼을 탭한다. 같이 옮기기 데모는 끄는 블록과 이어 둔 블록의 점선 그림자가 같은 거리만큼 같이 내려가서 "묶어 두면 같이 온다" 를 보여 준다. 자리는 둘 다 묶음 밖 블록과 안 겹치고 하루 안에 남는 가장 가까운 곳으로 계산한다. 7·8단계는 할일 목록 시트 안에서 하는데, 플래너 위 카드는 시트에 가려서 같은 카드를 시트 아래쪽에 한 장 더 띄웠다.

## 잠금 — 들여다보기만 하는 하루가 손에 밀리지 않게

첫 단계가 잠금 풀기인 건 잠금 버튼을 새로 달았기 때문이다. 고른 블록과 이어 둔 블록은 길게 누르지 않고 바로 끌리게 해 뒀더니, 하루를 스크롤하며 체크만 하는 동안에도 손끝에 블록이 딸려 왔다. 왼쪽 아래 실행 취소·다시 실행 옆에 자물쇠를 두고, 잠그면 스크롤과 왼쪽 체크(완료)만 되게 했다. 배치·선택·이동·길이·묶기는 전부 먹지 않는다.

![잠금 풀기 단계. 카드가 왼쪽 아래 자물쇠를 가리키고, 주황 자물쇠 위에서 손가락이 탭을 시연한다](/blog/planner-tutorial/unlock-step.png)

진 대안은 넷이다. 설정 화면의 토글은 들여다볼 때 켜고 편집할 때 끄는 스위치라기엔 너무 멀다. 잠겨도 선택은 되게 하면 연결 버튼과 메모·삭제 버튼이 떠서 "누르면 되는데 안 된다" 가 된다. 잠긴 타임라인이 아무 반응도 안 하면 고장으로 읽힌다 — 그래서 잠긴 채 블록을 누르면 자물쇠가 좌우로 흔들리고 경고 햅틱이 난다. iCloud 로 공유하는 설정으로 두면 아이패드에서 잠가 둔 것이 아이폰 편집을 막는다. 그래서 잠금은 기기마다 따로 남는다.

## 기기에 남는 값은 다음 실행으로 샌다

튜토리얼은 잠근 채 시작하고, 사용자가 풀기 전에 건너뛰면 그 잠금을 되돌려 준다. 처음엔 "튜토리얼이 잠갔다" 를 메모리에만 들고 있었다. 회귀 테스트를 돌리자 묶음 드래그 UI 테스트가 전부 "할일 선택 시트가 안 열림" 으로 죽었다. 실패 화면의 접근성 계층을 보니 자물쇠 라벨이 "잠금 풀기" — 잠겨 있었다.

같은 시뮬레이터에서 먼저 돈 유닛 테스트의 호스트 앱이 원인이었다. 호스트 앱은 테스트 인자 없이 뜨니 첫 실행 튜토리얼이 그대로 시작돼 타임라인을 잠갔고, 잠금은 기기별 `UserDefaults` 라 디스크에 남았다. UI 테스트의 리셋 인자는 저장소만 메모리로 바꾸고 `UserDefaults` 는 건드리지 않는다. 같은 뿌리의 제품 버그도 보였다: 잠근 채 앱이 죽으면 다음 실행의 튜토리얼은 그 잠금을 사용자가 건 것으로 읽고, 건너뛰어도 풀지 않는다.

그래서 "튜토리얼이 잠갔다" 를 디스크에 적고, 리셋·캡처 인자로 뜨면 잠금을 푼 채 시작하게 했다. 여덟 단계는 시뮬레이터에서 처음부터 끝까지 손으로 따라 하는 UI 테스트가 지킨다 — 잠긴 채 끌어도 시트가 안 뜨는지, 묶은 두 블록이 같은 거리만큼 가는지, 끝나면 잠금이 풀려 있는지까지.
