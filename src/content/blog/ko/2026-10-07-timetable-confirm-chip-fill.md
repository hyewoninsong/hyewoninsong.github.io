시트 우상단의 ✓ 는 이제 눌러도 되는 상태일 때 검게 채워지고, 아직 안 되는 상태일 때는 회색으로 채워진다. 전에는 체크 글리프만 살짝 흐려졌는데, 바로 옆 X 와 나란히 놓고 비교해야 겨우 차이가 보였다.

## 채움이 "지금 눌러도 된다" 를 말한다

기준은 아이폰 사진 앱의 선택 화면이다. 아무것도 고르지 않았을 때 우상단 ✓ 는 회색 원이고, 하나라도 고르면 진한 원으로 바뀐다. 버튼이 있다는 사실은 늘 보이고, 누를 수 있는지는 채움의 진하기가 알려 준다.

![위에서부터 라이트 비활성·활성, 다크 비활성·활성. 비활성도 원이 채워져 있고, 왼쪽 X 는 그대로 빈 유리 원이다](/blog/timetable-confirm-chip-fill/chip-states.png)

이 문법을 활성 조건이 있는 확인 버튼 전부에 넣었다.

| 자리 | ✓ 가 회색인 때 |
|---|---|
| 일정 편집 (아이폰 시트 · 아이패드 팝오버) | 시각이 뒤집혔거나 표시 범위 밖, 색이 없음 |
| 새 시간표 | 세로 축을 아직 안 고름 |
| 설정 · 표시 방식 | 고친 값이 유효하지 않음 |
| 색 에디터 | hex 가 색이 아님 |

조건 자체는 새로 만들지 않았다. 시트마다 이미 갖고 있던 "저장할 수 있나" 를 그림으로 옮겼을 뿐이다. 반대로 늘 눌리는 ✓, 예를 들어 시간표 목록의 편집 종료는 채우지 않았다. 항상 켜져 있는 버튼까지 채우면 채움이 아무 말도 하지 않게 된다.

색은 강조색 파랑이 아니라 글자색 그대로다. 라이트에서는 검은 원, 다크에서는 흰 원이 된다. 처음 이 글을 쓸 때는 "시트의 파랑은 하단의 주 버튼 하나" 라고 적었는데, 같은 날 그 하단 버튼 자체를 없앴다. 아래 마지막 절에 적는다.

## 시스템 버튼은 비활성이 되면 채움을 버린다

처음에는 직접 그릴 생각이 없었다. iOS 26 에는 채워진 유리 버튼 스타일 `.glassProminent` 가 있고, 여기에 `.tint` 로 글자색을 주면 활성 상태는 원하던 그림이 그대로 나온다.

문제는 비활성이었다. `.disabled` 가 걸리는 순간 채움이 통째로 사라지고, 옆의 X 와 똑같은 빈 유리 원에 흐린 체크만 남는다. 고치기 전 모습과 같다.

![시스템 prominent 스타일. 위가 비활성, 아래가 활성 — 비활성에서는 채움이 빠져 X 와 같은 빈 원이 된다](/blog/timetable-confirm-chip-fill/system-prominent-disabled.png)

`.disabled` 를 빼고 터치만 막으면 그림은 나오겠지만 VoiceOver 와 UI 테스트가 "이 버튼은 눌린다" 고 믿게 된다. 그림을 얻자고 접근성 트리에 거짓말을 넣을 수는 없었다.

그래서 `ButtonStyle` 을 하나 만들었다. 스타일 안에서 환경값 `isEnabled` 를 읽어 채움 색을 고르고, 비활성이면 유리의 눌림 반응(`.interactive()`)도 뗀다. 호출하는 쪽은 예전처럼 `.disabled(…)` 만 건다. 활성 여부를 따로 넘겨받지 않으니 "동작은 막혔는데 그림은 활성" 인 상태가 생길 틈이 없다. 지난달 아이패드 팝오버에서 정확히 그 어긋남 때문에 "확인을 두 번 눌러야 닫힌다" 는 제보를 받은 적이 있다.

내비게이션 바에 넣을 때는 한 가지가 더 필요하다. iOS 26 은 툴바 항목마다 유리 원을 깔아 주기 때문에, 그대로 두면 유리 원 안에 칩이 한 겹 더 들어간다. `ToolbarItem` 에 `.sharedBackgroundVisibility(.hidden)` 을 걸어 시스템 원을 끄고, 칩 지름을 시스템과 같은 44pt 로 맞췄다.

## 아이패드 팝오버에서는 버튼이 모서리에 끼어 있었다

같은 날 아이패드의 일정 편집 팝오버도 손봤다. 헤더의 X 와 ✓ 가 팝오버 가장자리에서 좌우 12pt, 위 5pt 떨어져 있었는데, 팝오버의 모서리가 크게 둥글어서 버튼이 그 곡선에 끼어 보였다. 아이폰 시트에서 툴바 버튼이 떨어져 있는 거리를 재서 좌우 16pt, 위 15pt 로 맞췄다.

![왼쪽이 전, 오른쪽이 후. 버튼이 둥근 모서리에서 떨어져 나왔다](/blog/timetable-confirm-chip-fill/ipad-header-inset.png)

## 남은 것

비활성 ✓ 는 "왜 안 되는지" 까지는 말하지 않는다. 일정 편집 시트는 시각 줄 아래에 사유 한 줄이 있지만, 새 시간표 시트는 안내 문구에 기대고 있다. 그리고 이런 변경은 접근성 값으로는 검증이 안 된다. 그림이 틀려도 `isEnabled` 는 맞게 나오기 때문에, 활성·비활성과 라이트·다크 네 장을 X 와 한 화면에 담아 눈으로 본다.

## 2026-10-07 — 하단의 긴 버튼을 없애고 같은 칩으로 올렸다

같은 날 오후, 채운 칩의 쓰임을 넓혔다. 인쇄, 이미지 공유, 잠금화면 배경처럼 시트 바닥에 가로로 길게 놓여 있던 주 버튼을 없애고, 그 동작을 우상단의 채운 칩으로 올렸다. 편집·설정·새 시간표 시트는 이미 우상단 ✓ 였으니, 하단 버튼을 쓰던 시트만 다른 문법으로 남아 있던 셈이다.

![인쇄 시트. 우상단 칩이 프린터 글리프이고, 프린터를 아직 안 골라 회색이다. 사유는 패널 바닥에 한 줄로 남아 있다](/blog/timetable-confirm-chip-fill/print-chip.png)

글자가 사라지니 글리프가 동작을 말해야 한다.

| 시트 | 칩의 글리프 |
|---|---|
| 인쇄 | 프린터 |
| 이미지 공유 · 빈 시간 보내기 | 공유 화살표 |
| 잠금화면 배경 | 아래 화살표(사진에 저장) |
| 약속 시간 제안 | 복사 |
| 내 시간표 추가 · 교시 불러오기 | ✓ |

고르고 확정하는 두 시트는 원래 버튼 아이콘이 `+` 와 가져오기 화살표였는데 ✓ 로 바꿨다. 우상단의 `+` 는 "새로 만들기" 로 읽히고, 이 앱에서 "고른 것으로 확정" 은 이미 ✓ 다.

![이미지 공유 시트. 프리뷰가 바닥까지 내려오고 주 동작은 우상단 하나다](/blog/timetable-confirm-chip-fill/share-chip.png)

### 옮기면서 지킨 것

버튼 제목이 없어지면 VoiceOver 와 UI 테스트가 읽을 이름도 같이 없어진다. 그래서 칩을 만드는 부품이 접근성 이름을 필수로 받게 했고, 식별자는 예전 버튼의 것을 그대로 물려줬다. 캡처 스크립트와 테스트는 한 줄도 안 고치고 같은 버튼을 찾는다.

인쇄 시트에는 버튼 바로 위에 "인쇄할 프린터를 선택해 주세요" 같은 사유 한 줄이 있었다. 버튼과 함께 지우면 회색 칩이 왜 회색인지 말해 주는 글이 화면에서 사라진다. 그 줄은 패널 바닥에 남겼다.

잠금화면 배경 시트는 우상단에 이미 전체 화면 미리보기와 공유가 있었다. 저장까지 올라가니 오른쪽이 셋이 되고, 가운데 있던 제목이 왼쪽으로 밀려 붙는다. 저장만 채운 칩이라 나머지 둘과는 갈린다. 다만 공유(위 화살표)와 저장(아래 화살표)이 나란히 놓이는 건 조금 더 지켜볼 일이다.

![잠금화면 배경 시트. 오른쪽에 전체 화면·공유·저장 셋이 놓이고 제목은 왼쪽으로 붙는다](/blog/timetable-confirm-chip-fill/lock-screen-three.png)

### 올리지 않은 버튼

전부 올리지는 않았다. 기준은 "아이콘 하나로 줄여도 뜻이 남는가" 였다.

- **캘린더로 내보내기.** 버튼 제목이 상태에 따라 "추가", "업데이트", "옮기기" 로 바뀐다. 아이콘으로 줄이면 지금 누르면 무엇이 되는지가 사라진다. Apple 캘린더와 파일, 갈래도 둘이다.
- **비슷한 일정도 같이 바꿀지 묻는 확인.** 선택지가 둘이라 주 동작이 하나가 아니다.
- **삭제.** 되돌릴 수 없는 동작은 본문 맨 아래 단독 그룹에 둔다는 규칙이 먼저다.
- **시간표 목록의 하단 줄.** 우상단에 이미 버튼이 둘 있고, 하단 줄은 바로 전날 자리를 맞췄다. 옮기려면 목록 시트의 툴바를 다시 짜야 해서 따로 정하기로 했다.

채운 칩은 시트에 하나만 둔다. 둘이 되는 순간 채움은 다시 아무 말도 하지 않는다.
