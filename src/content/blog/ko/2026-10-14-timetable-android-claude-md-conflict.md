슈퍼시간표 안드로이드 저장소에서는 이제 함정 하나를 배워도 `CLAUDE.md` 를 고치지 않는다. 함정 문서 파일 하나만 더하면 목록은 main 에서 저절로 만들어진다. 그전에는 PR 을 올릴 때마다 이 파일이 충돌했고, 매번 손으로 풀었다.

## 충돌은 한 줄에서 났다

`CLAUDE.md` 는 에이전트가 세션을 시작할 때 읽는 프로젝트 지침이다. 여기에 "이 프로젝트에서 밟았던 함정" 목록을 넣어 두면, 다음 세션이 같은 구멍에 빠지기 전에 한 번 훑는다. 쓸모가 있어서 계속 늘렸다.

문제는 늘리는 방식이었다. 목록이 한 줄이었다. `Pitfalls:` 로 시작해서 파일 이름과 한 줄 요약을 가운뎃점으로 이어 붙인 줄이고, 새 함정은 늘 그 줄 끝에 붙었다. 세어 보니 이랬다.

| 잰 것 | 값 |
|---|---|
| 10월 들어 main 에 들어간 커밋 | 48개 |
| 그중 `CLAUDE.md` 를 고친 커밋 | 31개 |
| 그 한 줄의 길이 | 6,433자 |
| 함정 문서 파일 | 51개 |
| 그 줄에 실제로 적혀 있던 것 | 38개 |

git 은 줄 단위로 합친다. 두 브랜치가 같은 줄의 끝에 서로 다른 것을 붙이면, 내용이 아무리 무관해도 충돌이다. 열려 있는 PR 이 둘이고 둘 다 뭔가를 배웠다면 반드시 부딪힌다. 여러 세션을 동시에 돌리는 저장소에서는 그게 매일이었다.

마지막 두 줄도 눈에 띈다. 손으로 관리한 목록은 충돌만 낸 게 아니라 13개를 빠뜨리고 있었다. 충돌을 푸는 과정에서 한쪽 항목이 떨어져 나간 것도 있을 것이다.

## PR 은 조각만 더하고, 목록은 main 에서 만든다

같은 문제를 아이폰판 저장소가 한 달 전에 결정 기록에서 겪었다. 거기서 정한 규칙을 그대로 가져왔다.

- PR 은 **새 파일만** 더한다. 함정이면 함정 문서 하나, 결정이면 결정 기록 하나. 브랜치마다 파일 이름이 다르니 부딪힐 자리가 없다.
- 목록(색인)은 **생성 파일**이다. 함정이나 결정 파일이 main 에 들어오면 GitHub Action 이 스크립트를 돌려 색인을 고치고 봇 이름으로 커밋한다. 사람도 에이전트도 브랜치에서 색인을 건드리지 않는다.
- `CLAUDE.md` 에는 목록 대신 색인 파일을 불러오는 import 한 줄만 남는다. 세션이 시작할 때 읽는 내용은 전과 같다.

색인의 한 줄은 그 파일의 첫 줄 제목이다. 다만 이미 색인에 있는 줄은 스크립트가 한 글자도 바꾸지 않는다. 기존 38줄은 손으로 다듬은 짧은 요약이었고, 파일 제목보다 훑기 좋았다. 그래서 먼저 옛 줄을 색인으로 옮겨 놓고 나서 스크립트를 돌렸다. 순서를 바꿨으면 요약 38개가 전부 제목으로 덮였을 것이다.

## 진 대안들

- **`merge=union`.** `.gitattributes` 에 한 줄 적으면 git 이 양쪽 줄을 다 살려 합쳐 준다. 로컬 머지에서는 잘 된다. GitHub 의 PR 머지는 이 속성을 무시한다. 아이폰판이 먼저 써 보고 버린 이유가 이것이다.
- **한 줄을 여러 줄로 쪼개기.** 항목마다 한 줄씩이면 나아 보이지만, 두 PR 이 같은 마지막 줄 뒤에 한 줄씩 넣으면 그것도 충돌이다.
- **색인이 낡으면 PR 을 실패시키는 검사.** 그러면 모든 PR 이 색인을 커밋해야 한다. 충돌이 파일만 옮겨 간다.
- **목록을 지침에서 빼고 "여기 가서 읽어라" 만 남기기.** 충돌은 없어지지만, 세션이 굳이 찾아가 읽지 않는 한 함정 요약을 못 본다. 목록을 둔 이유가 사라진다.

## 올리다가 막힌 곳

Action 을 정의하는 워크플로 파일은 첫 push 에서 거절됐다. 명령줄 도구의 토큰에 `workflow` 권한이 없으면 GitHub 는 워크플로 파일이 든 push 를 받지 않는다. 그 파일만이 아니라 브랜치 전체가 거절된다. 나머지를 먼저 올리고 워크플로를 따로 올렸다.

둘 사이에 다른 PR 들이 들어오면서 색인은 벌써 함정 1개와 결정 9개만큼 뒤처져 있었다. 워크플로 파일 자신을 실행 조건에 넣어 둬서, 머지되는 순간 한 번 돌며 그 열 줄을 채웠다. 손으로 관리했다면 또 누군가 빠뜨렸을 열 줄이다.

## 지금 상태

색인 두 개는 봇이 관리하고, `CLAUDE.md` 는 모든 세션이 따라야 할 규칙이 바뀔 때만 고친다. 프로젝트 구조를 설명하는 줄에 붙어 있던 긴 설명들은 그대로 뒀다. 더 늘리지 않기로만 했으니, 그 줄에서 나던 충돌은 줄어들 뿐 당장 0 은 아니다. 새 안드로이드 프로젝트는 처음 세팅할 때부터 이 구조로 시작하게 초기 세팅 절차에도 넣었다.
