MindPDF 는 아이패드에서 PDF 전자책을 읽으며 색펜으로 밑줄을 긋고, 나중엔 밑줄만 다시 읽는 앱이다. 내가 쓰려고 만드는 앱이라 쓰는 방식이 곧 요구사항인데, 지금까지는 밑줄을 긋는 순간 마인드맵 노드가 하나 생기고 그게 전부였다. 노드가 밑줄이었다. 오늘 이 관계를 뒤집었다. 밑줄 장부가 데이터고, 마인드맵과 새로 생긴 리뷰 모드는 그 장부를 보는 두 개의 창이다.

## 밑줄은 자기 장부에 살고, PDF 는 건드리지 않는다

밑줄은 이제 SwiftData 의 `Highlight` 엔티티로 따로 저장되고, 페이지 위에 오버레이로 그려진다. PDF 파일은 한 번도 다시 쓰지 않는다. 마인드맵 노드를 탭하면 그 구절로 점프해 잠깐 깜빡인다 — 밑줄에서 노드로만 가던 연결이 드디어 양방향이 됐다.

손에 든 게 무엇인지도 구분한다. Apple Pencil 은 닿는 순간 밑줄이 시작되고, 손가락은 예전처럼 길게 눌러야 한다. 밑줄을 탭하면 팝오버가 뜬다 — 색, 형광펜/밑줄 스타일, 메모, 복사, 삭제, 맵에서 보기. 되돌리기와 다시 실행이 붙었다.

연달아 그은 밑줄은 이제 형제다. 예전에는 새 밑줄이 직전 노드의 자식으로 들어가서, 다섯 줄만 그으면 부모→자식→손자 사슬이 됐다. 읽는 중에 부모를 고르는 사람은 없다.

## 다시 읽는 화면이 셋으로 갈렸다

이 앱의 하루는 마인드맵이 아니라 밑줄을 다시 읽는 데서 지나간다. 그래서 리뷰 모드를 따로 두고 탭 셋으로 나눴다.

| 탭 | 보이는 것 |
|---|---|
| 밑줄만 보기 | 페이지 그대로, 밑줄 아닌 곳만 흐려진다 |
| 압축 읽기 | 밑줄 친 줄만 이미지로 잘라 페이지 순서로 이어 붙인 띠. 탭하면 그 자리로 간다 |
| 목록 | 챕터별로 묶인 목록. 색 필터, 검색, 맵으로 올리기 |

## 부모는 독자가 아니라 책이 정한다

챕터는 PDF 목차에서 가져오고, 목차가 없으면 글자 크기로 제목을 찍어 낸다. 아무것도 선택하지 않은 채 그은 밑줄은 자기 챕터 아래로 들어간다. 색에는 프로젝트마다 뜻을 붙일 수 있다 — 기본은 노랑=핵심, 초록=실행, 파랑=인용, 빨강=의문.

## 스캔본과 손글씨도 같은 장부로 들어온다

스캔한 책은 글자가 없어서 밑줄이 붙을 줄이 없다. 페이지 단위 OCR 캐시를 두고, 보이는 페이지를 먼저 읽고 나머지는 뒤에서 훑는다. 밑줄은 OCR 줄에 스냅하고, 인용문은 나중에 채워진다. 검색은 밑줄과 본문을 함께 뒤진다. 내보내기는 Markdown, 주석 달린 PDF, 맵 PNG, OPML 넷이다.

Pencil 로 쓴 손글씨 묶음과 사각형으로 잘라 낸 영역도 노드가 된다. 기기 안에서 도는 FoundationModels 가 짧은 라벨, 들어갈 부모, 챕터 요약을 제안하는데, 전부 칩으로 보여만 주고 자동으로 적용하는 건 하나도 없다.

## 밀린 안 셋과 미룬 결정 하나

- **노드=밑줄을 유지하고 기능만 얹기** — 리뷰 목록, 내보내기, 표시는 남기고 노드만 지우기. 전부 노드가 있어야 가능했고, 맵에서 노드를 지우면 읽은 흔적이 같이 사라진다. 매일 쓰는 표면이 맵이 아니라 밑줄 다시 읽기라서 밀렸다.
- **PDFKit 주석으로 PDF 에 직접 쓰기** — 지금까지 그렇게 했다. 획 하나마다 500쪽 파일을 다시 쓰고, 되돌리기가 없고, "밑줄만 보기"는 파일을 다시 파싱하지 않으면 불가능했다. 비용에서도, 원본은 건드리지 않는다는 원칙에서도 밀렸다.
- **새 밑줄을 직전 노드 아래에 자동으로 넣기** — 역시 지금까지 그랬다. 위에 쓴 사슬이 그 결과다. "책이 정한다"로 바꿨다 — 목차 챕터가 부모, 아니면 형제.
- **iCloud 동기화** — 일부러 뺐다. SwiftData 를 CloudKit 에 얹으려면 관계가 전부 옵셔널이어야 하고 unique 제약이 없어야 한다. 스키마를 다시 짜는 일이라 따로 결정한다.

## 테스트 400개가 매번 다른 자리에서 죽었다

유닛 테스트를 전부 돌리면 번들 전체가 크래시했다. 매번 다른 테스트에서 죽었고, 죽은 테스트만 골라 돌리면 통과했다.

원인은 챕터 추출을 하는 백그라운드 `Task` 였다. 그 클로저가 SwiftData 의 `PDFFile` 모델을 잡고 있었고, 테스트가 끝나 컨테이너가 사라진 뒤에 속성 하나를 읽는 순간 어설션이 났다. 클로저에 `ModelContext` 를 같이 잡아 두어도 소용없었다 — 컨텍스트는 컨테이너를 붙들어 두지 않고, `context.container` 자체가 어설션을 냈다. 컨테이너까지 잡아도 끝이 아니었다. 이미 삭제되고 저장까지 된 행이면 CoreData 가 "could not fulfill a fault" 를 던지고 프로세스가 종료됐다.

고친 방법은 Task 를 만드는 자리에서 id, 파일 URL, 컨텍스트, 컨테이너를 동기적으로 잡아 두는 것. await 뒤에는 id 로 행을 다시 조회하고, 아직 있을 때만 쓴다. Task 는 뷰 모델이 들고 있다가 화면을 떠날 때 취소한다.

더 빨리 잡을 수 있었다. 크래시 리포트(`.ips`)를 먼저 열었으면 죽은 스레드에 getter 이름이 그대로 적혀 있었다. 대신 실패한 테스트를 쫓느라 반나절을 썼다.

## 회전은 이미 적용돼 있었다

OCR 렌더러가 회전된 스캔 페이지에서 아무것도 읽지 못했고, cropBox 원점이 0 이 아닌 페이지에서는 모든 줄이 정확히 원점만큼 밀렸다. `PDFPage.draw(with:to:)` 가 페이지 회전과 cropBox 원점을 이미 적용하는데, 렌더러가 `transform(for:)` 를 한 번 더 곱하고 있었다. 문서를 믿는 대신 40줄짜리 픽셀 탐침으로 확인했다 — 검은 막대를 그리고, 어두운 픽셀의 경계를 읽어 오는 것.

## 눈으로는 아직 못 봤다

앱 저장소에 PR 넷이 쌓여 있고, iPad Pro 11인치 시뮬레이터에서 유닛 테스트 842개가 돈다. 시뮬레이터에서 손으로 만져 본 건 아직 없다. iCloud 는 열려 있는 결정이다.
