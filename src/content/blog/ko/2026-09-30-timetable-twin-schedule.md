교시형 시간표에서 수업 블록을 줄이거나 다른 요일로 옮기면, 선택을 푸는 순간 원래 크기와 자리로 돌아가던 문제를 고쳤다. 원인은 끌기 코드가 아니었다. 같은 id 를 가진 일정이 두 개 저장돼 있었다.

## 선택을 풀면 원래대로 돌아갔다

제보는 화면 녹화 두 개였다. 2–3교시짜리 국어를 2교시로 줄이면, 선택돼 있는 동안은 줄어든 모양 그대로다. 빈 곳을 눌러 선택을 푸는 순간 다시 2–3교시가 된다. 공학수학을 월요일로 옮겨도 선택을 풀면 수요일로 돌아갔다. 그런데 알고리듬은 옮긴 자리에 그대로 남았다. 모든 블록이 그런 건 아니었다.

끌기와 저장 코드는 먼저 읽어 봤다. 교시형 시간표는 교시 하나를 가상 한 시간으로 놓고 그리는데, 저장할 때는 실제 시각으로 되돌린다. 이 변환도 맞았고, 새로 만든 교시형 시간표에서 똑같이 줄여 보면 줄어든 채로 남았다. 코드는 멀쩡한데 사용자 기기에서만 나는 버그였다.

## 단서는 혼자 빗금을 칠한 블록이었다

두 번째 녹화에 이상한 장면이 하나 있었다. 빈 칸에 혼자 있는 블록이 겹침 빗금으로 그려져 있었다. 빗금은 같은 시간에 일정이 둘 이상일 때만 칠해진다. 그 자리에 눈에 안 보이는 무언가가 있다는 뜻이다.

같은 시간표에 id 가 같은 일정이 둘 있다면 증상이 전부 설명된다.

- 저장은 id 로 첫 번째 것을 찾아 바꾼다. 두 번째는 옛 자리에 그대로 남는다.
- 선택된 동안에는 선택 레이어가 첫 번째 것을 그린다. 그래서 바뀐 모양이 보인다.
- 선택을 풀면 일반 블록 목록(`ForEach`)으로 돌아간다. `ForEach` 는 id 하나에 뷰 하나만 만들어서, 안 움직인 두 번째가 화면에 남는다.
- 겹침 계산은 둘 다 세기 때문에 빗금이 칠해진다.

시뮬레이터에서 같은 일정을 일부러 두 번 넣고 줄여 봤다. 녹화와 똑같이 돌아갔다.

## 쌍둥이는 확인 버튼 연타에서 나왔다

어디서 쌍둥이가 생겼는지는 코드만 봐서는 찾지 못했다. 복제, 되돌리기, 교시 편집이 모두 새 id 를 쓰고 있었다. 사용자에게 물어서 조작 순서를 알아냈다. 새 일정 시트에서 스타일 팝오버를 열고, 스타일을 바꾼 뒤, 우상단 확인 버튼을 빠르게 여러 번 눌렀다고 했다.

이 순서에 딱 맞는 구멍이 있었다. 스타일 팝오버가 떠 있을 때 누른 첫 확인은 팝오버를 닫는 데 먹힌다. 그래서 그 탭을 저장으로 이어 주되, 방금 고른 색이 반영되도록 저장을 팝오버가 사라진 뒤로 한 박자 미뤄 두었다. 그 사이, 또는 시트가 내려가는 애니메이션 동안 확인을 한 번 더 누르면 저장이 바로 한 번 더 불린다. 새 일정이 같은 id 로 두 번 들어간다.

## 문을 두 군데 막았다

- **시트**: 저장이 예약돼 있는 동안 누른 확인은 버린다. 새 일정은 시트 하나에서 한 번만 저장된다. 기존 일정 편집은 두 번 저장돼도 같은 값이라 그대로 뒀다.
- **저장소**: 일정이 들어오는 단일 지점에서 id 가 유일한지 확인한다. 같은 시간표에 이미 있는 id 면 넣지 않는다. 다른 시간표에 있는 id 면 새 id 를 준다. 막을 때마다 어느 코드에서 들어왔는지를 함께 보고한다.

시트만 고치면 다음에 생길 새 경로가 또 뚫는다. 그렇다고 그리기에서 중복을 걸러 내면 화면만 멀쩡하고 저장 데이터는 계속 어긋난다. 그래서 둘 다 막았다. 이미 쌍둥이가 저장된 기기는 앱을 다시 켜면 기존 교정 단계가 한쪽에 새 id 를 준다. 겹친 블록 두 개가 따로 보이니 하나를 지우면 된다.

## 왜 늦게 잡았나

앱 시작 때 중복 id 를 걷어내는 교정은 이미 있었다. 다른 기기에서 가져온 시간표 때문에 알람이 안 울리던 버그를 고치면서 넣은 것이다. 하지만 실행 중에 들어오는 중복을 막는 문은 없었다. 교정은 다음 실행까지 쌍둥이를 살려 두었다.

UI 테스트로 연타를 재현하려던 시도도 실패했다. XCUITest 는 탭마다 앱이 한가해질 때까지, 곧 애니메이션이 끝날 때까지 기다린다. 그래서 두 번째 탭은 언제나 시트가 닫힌 뒤에 떨어졌다. 사람 손가락만 만들 수 있는 타이밍이라, 그 경로는 코드로 따라가 확인했다.

## 남은 것

실행 중 중복을 막을 때 오는 보고가 0으로 머무는지 지켜본다. 코드는 멀쩡한데 사용자 기기에서만 나는 버그를 만나면, 다음부터는 사용자 데이터의 모양(중복 id, 범위 밖 값)부터 만들어서 재현해 본다.
