## 문서 감사 결과

- `docs/specs/website.md` 업데이트 (스펙 1건)
  - 앱 frontmatter 예시가 예전 단일 `status` 필드를 쓰고 있어서 실제 `src/content.config.ts`의 `platforms` 객체, 선택 필드 `appStoreUrl`, 빈 `icon` 허용에 맞게 교체하고 필드 표를 추가했다.
  - 4.2.2 앱 상세 페이지 섹션이 "md 본문이 그대로 렌더링"이라고 적혀 있었는데, 실제로는 앱마다 정적 `<slug>.astro` 페이지가 `[slug].astro` 동적 라우트를 가리고 카피를 하드코딩한다. 이 구조와 `img()` 헬퍼, `public/apps/<slug>/<locale>/` 스크린샷 규칙, SuperTimetable 페이지의 섹션 순서를 문서화했다.
  - 프로젝트 구조의 `public/` 트리에 `apps/<slug>/{en,ko}/` 항목을 추가하고, "새 앱 추가 시" 워크플로우 단계를 현재 스키마와 스크린샷 규칙에 맞게 고쳤다.
- `docs/plans/website.md`는 과거 구현 계획서라 그대로 두었다.

## 테스트 감사 결과

- 저장소에 테스트 프레임워크와 테스트 파일이 전혀 없었다. 의존성 없이 Node 내장 `node:test`를 쓰는 `tests/app-screenshots.test.mjs`를 추가하고 `package.json`에 `npm test` 스크립트를 넣었다.
- 검사 항목: en/ko 정적 앱 페이지 목록 일치, timetable 페이지가 참조하는 스크린샷 19장 목록, `img()` 헬퍼가 `/apps/<slug>/<locale>/`를 가리키는지, en/ko 페이지의 참조 이름 집합 일치, 참조된 모든 png가 실제 존재하는지, en/ko 폴더 파일 목록 일치.
- 결과: 6개 모두 통과. 스크린샷 하나를 임시로 빼면 2개가 실패하는 것을 확인한 뒤 복원했다.

## 요약

최근 커밋은 SuperTimetable 소개 페이지와 언어별 스크린샷을 갈아엎은 작업이었고, 스펙 문서는 초기 설계(단일 status 필드, md 본문 렌더링)에 머물러 있어 실제 코드와 어긋나 있었다. 스펙을 현재 구조에 맞게 동기화했고, 스크린샷 파일명 불일치나 누락을 빌드 전에 잡아낼 수 있는 가벼운 회귀 테스트를 처음으로 도입했다. 소스 코드는 수정하지 않았다. 변경은 PR #22로 올렸으며 병합 여부는 사용자 판단에 맡긴다.
