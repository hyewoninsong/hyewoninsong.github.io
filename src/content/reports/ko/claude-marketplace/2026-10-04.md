## 문서 감사 결과

`specs/` 디렉터리는 없다. 업데이트한 문서 4개:

- `settings/docs/disk-hygiene.md` — DerivedData 안전장치 설명이 코드와 반대였다("xcodebuild 실행 중이면 단계 전체 건너뜀" → 폴더별 60분 최근 쓰기 판정). tmp Xcode 부산물 행, 30GB 미만 시 30분 간격 비상 GC 기동, fseventsd CPU 50% 경고를 추가하고 "건너뜀" 메시지 언급을 클론 단계로 한정.
- `docs/modules/hooks.md` — 존재하지 않는 `hooks/discord-notify.js` 행을 제거하고 외부 저장소임을 명시. 표에 6개만 있던 훅 인벤토리를 실제 `hooks/` 의 훅·콜렉터·헬퍼 전체로 확장. 이벤트 표를 `global-settings.json` 등록 내용과 일치시킴.
- `hooks/CLAUDE.md` — 인벤토리 위치와 테스트 실행 방식(pytest 가 아니라 직접 실행) 한 줄.
- `skills/disk-gc/SKILL.md` — `pgrep -x xcodebuild` 판정이 클론·모듈 캐시 단계에만 남았다는 범위 메모.

정확해서 그대로 둔 것: ADR `2026-10-04-disk-gc-per-target-busy-check.md`, `docs/references/tmp-xcode-gc-pitfall.md`, `settings/docs/memory-hygiene.md`, `docs/modules/distribution.md`.

## 테스트 감사 결과

모든 `hooks/*.test.py` 가 `python3.12` 직접 실행으로 통과(27개). 수정·추가한 파일 6개:

- `hooks/disk-gc-schedule.test.py` — **origin/main 에서 깨져 있던 테스트 수정.** 새 60분 busy 가드가 방금 만든 orphan 폴더를 살려 두어 실패하던 것을 orphan 을 오래된 것으로 만들어 고침. 신선한 orphan 생존, 빌드 중에도 오래된 orphan 삭제 케이스 추가.
- `hooks/scheduled-disk-gc.test.py` (신규, 4) — 여유 30GB 미만이면 `--hours 2` + "disk pressure", 아니면 6 또는 `DISK_GC_TMP_HOURS`.
- `hooks/rc-session-gc.test.py` (신규, 6) — `pid name` 파싱, apply·dry-run, busy 세션 유지, 옛 밑줄 형식, `LANG` 기본값.
- `hooks/check-updates.test.py` (신규, 4) — 비상 GC 백그라운드 기동과 30분 스로틀, fseventsd CPU 경고. 네트워크 없음(`curl` 스텁).
- `hooks/mem-gc-plist.test.py` (신규, 4) — plist `LANG=en_US.UTF-8`, `StartInterval 1800`, 설치 스크립트 `StartInterval=7200`.
- `hooks/tmp-xcode-gc.test.py` — `DISK_GC_TMP_HOURS` 기본값, `--hours` 우선 케이스 2개 추가.

## 요약

하루 동안 디스크·메모리 GC 훅이 집중적으로 바뀌었는데 `disk-hygiene.md` 의 핵심 표 한 줄이 코드와 정반대로 남아 있었고, 훅 인벤토리 문서는 실제 파일 20여 개 중 6개만 다루며 없는 파일을 가리켰다. 테스트 쪽은 이번 변경이 기존 테스트 하나를 깨뜨린 채 머지돼 있었고 셸 훅 4개는 테스트가 전혀 없었다. 모두 문서·테스트 범위에서 바로잡았다.

소스 수정 금지 범위라 고치지 않고 PR 본문에 적어 둔 발견 3건:

1. `install.sh` 가 `rc-session-gc.sh`, `launch-guard.js`, `simulator-lifecycle.js`, `shell-heredoc.js`, `simctl-throwaway.py` 를 다운로드하지 않는다. 앞의 셋은 설정에 등록돼 있거나 `mem-gc.sh` 가 형제 파일로 찾으므로 다운로드 설치에서 조용히 빠진다.
2. `rc-session-gc.sh` 는 옛 밑줄 형식(`rc-foo_1234`)이 들어오면 경고 없이 `0개 끔` 으로 끝난다. `name` 이 비어 `rc-*` 분기 전에 skip 되기 때문이다. 테스트는 현재 동작을 고정해 두었다.
3. `hooks/launch-hygiene.test.js` 는 origin/main 에서도 이미 실패 중이다. `disk-hygiene.md` 안의 `"NQ …"` 예시 문구를 vc- 규칙 위반으로 잡는다.

같은 파일을 건드리는 열린 PR: #273, #291, #332(이전 일일 감사), #195.
