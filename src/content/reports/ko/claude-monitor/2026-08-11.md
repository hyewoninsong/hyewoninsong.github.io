## 오늘의 변경 사항

- `2c83e60` improve: load root .env when starting server
  - `packages/server/package.json`의 `dev`/`start` 스크립트에 `--env-file=../../.env` 플래그 추가
  - `start.sh`가 `bun run src/index.ts` 직접 실행 대신 `bun run start`를 사용하도록 변경

## 문서 감사 결과

- `docs/design-docs/architecture.md` — Authentication 섹션에 루트 `.env` 로딩 방식(`--env-file=../../.env`)과 `start.sh`가 동일한 `.env`를 사용한다는 설명 추가
- `CLAUDE.md` — Commands 섹션의 `bun run start` 설명 수정 (프론트엔드 빌드는 하지 않고 서버만 시작하며 루트 `.env`를 로드함, 빌드는 `start.sh`가 담당), Key Constraints의 인증 항목에 `.env` 로딩 경로 추가
- `docs/design-docs/project-aggregation.md`, `docs/product-specs/token-usage-analysis.md` — 이번 변경과 무관하여 수정 불필요 (최신 상태)

## 테스트 감사 결과

모든 테스트가 최신 상태

- 이번 커밋은 소스 코드 변경 없이 Bun CLI 플래그와 셸 스크립트만 수정함. `MONITOR_TOKEN`을 읽는 `index.ts` 로직은 그대로이며, env 파일 로딩은 Bun 런타임 기능이라 단위 테스트 대상이 아님

## 요약

최근 24시간 내 커밋 1건은 서버 시작 시 루트 `.env` 파일을 로드하도록 스크립트를 개선한 변경이야. 이에 맞춰 아키텍처 문서와 CLAUDE.md의 인증/명령어 설명을 업데이트했고, CLAUDE.md에 있던 오래된 설명(`bun run start`가 프론트엔드를 빌드한다는 부분)도 실제 동작에 맞게 바로잡았어. 소스 코드 변경이 없어서 테스트 추가는 필요하지 않았고, 스펙 문서도 이번 변경과 무관해서 수정하지 않았어.
