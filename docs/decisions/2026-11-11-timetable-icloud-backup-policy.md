# SuperTimetable 정책에 iCloud 백업(iOS) 고지를 다시 넣음 (2026-11-11)

Date: 2026-11-11
Status: accepted — `2026-10-13-timetable-icloud-backup-removed.md` 를 대체한다

## Context

앱이 2026-11-11 에 iCloud 백업을 다른 설계로 되살렸다. 옛 판(계정당 파일 하나, 자동 복원 제안)이 아니라,
기기(설치)마다 제 묶음에만 쌓이는 사본이고 복원은 사용자가 목록에서 하나를 골라 확인한 뒤에만 일어난다.
앱 `main` 에는 이미 들어갔고 아직 출시 전이다.

스위치가 **기본 켜짐**이라, 그 버전을 받은 사용자는 아무것도 누르지 않아도 시간표·캘린더 일정의 사본이 본인 iCloud 에
올라간다. 게시본은 "기기 안에만 저장 · 클라우드 동기화·백업 기능이 없습니다" 라고 말하고 있어서, 기능이 나가는 순간
틀린 문장이 된다. 방침이 기능보다 먼저 나가야 한다.

## Decision

- **1조**: "기기 안에만 저장" → "기기에 저장", "클라우드 동기화·백업 기능이 없습니다" → "기기 간 동기화 기능은 없습니다".
  "iCloud 백업 (iOS 앱)" 항목을 더한다 — 기본 켜짐·끌 수 있음, 사용자 본인의 iCloud, 개발자 접근 불가·개발자 서버 미전송,
  백업에 든 것(입력 내용 + 기기 모델 + 앱 버전), 복원은 사용자가 고를 때만, Android 에는 없음.
- **6조(보관)**: 기기마다 최근 7개, 끄거나 앱을 지워도 사용자가 지울 때까지 남는다.
  "보관 기간이 지난 데이터는 파기" 문장은 Firebase 데이터로 좁혔다 — iCloud 백업은 개발자가 파기할 수 없다.
- **7조(권리)**: "iCloud 백업 삭제 (iOS)" — 앱 안(하나씩 · 모두 삭제)과 iOS 설정의 iCloud 저장 공간 관리. 개발자가 대신 지울 수 없다고 적는다.
  iOS 설정의 메뉴 경로는 실기기로 확인하기 전이라 이름을 하나하나 적지 않았다.
- **적용 범위**: "이 항목은 iCloud 백업이 포함된 iOS 앱 버전부터 적용됩니다" 를 넣는다. 지금 판매 중인 버전에는 백업이 없어서,
  이 문장이 없으면 고지 기간 동안 방침이 지금 버전에 대해 틀린 말을 한다.
- **시행일 2026-11-18**: 방침 10조의 "시행 7일 전 고지"(2026-10-23 AdMob 개정과 같은 규칙). 백업이 든 iOS 버전은 이 날짜 전에 출시하지 않는다.
- 앱 페이지(`src/content/apps/{ko,en}/timetable.md`)는 이미 "기기에 저장됩니다 / stored on your device" 라 그대로 둔다.
  출시 전 기능을 앱 페이지에서 광고하지 않는다.
- `tests/privacy-pages.test.mjs`: "iCloud 를 말하면 실패" 를 뒤집어, 방침이 위 고지(본인 iCloud · 기본 켜짐 · 개발자 접근 불가 ·
  최근 7개 · 모두 삭제 · 앱 삭제 뒤에도 남음 · Android 에는 없음)를 담고, 방침·앱 페이지 어느 쪽도 "기기 안에만" 을 다시 말하지 않는지 본다.
  (옛 검사는 앱 페이지 문장이 바뀐 뒤로 main 에서 실패하고 있었다.)

## 다음에 비슷한 일이 오면

- 기본 켜짐으로 사용자 데이터가 기기 밖으로 나가는 기능은 **방침 게시 → 7일 → 출시** 순서다.
- 개발자가 닿을 수 없는 저장소(사용자 iCloud)는 "수집" 이 아니어도 보관 기간과 지우는 방법을 방침에 적는다 — 지울 수 있는 사람이 사용자뿐이다.
