# `overflow-x: auto` 행은 자식의 `box-shadow` 를 잘라 각진 회색 띠를 남긴다

**2026-09-17** · SuperTimetable 앱 페이지 스샷 행(`.shot-row`)

## 증상

아이폰 사파리로 `/ko/apps/timetable` 의 iPad 탭을 보면, 스샷 바로 아래에
**각진 회색 슬래브**가 붙어 있다. 그림자처럼 부드럽게 흐려지는 게 아니라
아래·좌·우가 자로 그은 듯 직선으로 끊긴다. 히어로 스샷(스크롤 행 바깥)은
멀쩡하고, 섹션 안 스샷만 그렇다.

실측(2x 캡처, 프레임 아래로 픽셀 밝기):

```
프레임 아래 0px   255   ← 프레임 지면
          +12px   215   ← 그림자 가장 진한 곳
          +24px   228
          +36px   250   ← 여기서 뚝. 지면색으로 복귀
```

## 메커니즘

```css
.shot-row {
  overflow-x: auto;
  padding: 0.75rem 0;   /* 12px */
}
```

- **`overflow-x: auto` 는 `overflow-y` 를 `visible` 로 둘 수 없다.** CSS 명세상
  한 축이 `visible` 이 아니면 다른 축의 `visible` 은 `auto` 로 강제 계산된다
  (`overflow-y: visible` 이라고 써도 무시된다). 즉 가로 스크롤 행은 **세로로도
  클리핑 박스**다.
- 자식의 `box-shadow: 0 20px 60px` 는 요소 아래로 `20 + 60/2 = 50px`,
  좌우로 `30px` 뻗는다. 패딩이 12px 뿐이니 **38px 이 잘려 나간다** — 남는 건
  그림자의 가장 진한 머리 부분(215)뿐이고, 흐려지는 꼬리가 통째로 사라져
  직선으로 끊긴 띠가 된다.
- iPad 스샷에서 유독 눈에 띄는 이유: 4:3 프레임이 행 폭을 가득 채워서
  잘린 띠가 **화면 가로 전체를 가로지른다.** iPhone 스샷(220px)도 같이 잘리지만
  좁아서 덜 보였다.

## 처방

그림자가 다 들어갈 만큼 패딩을 주고, 레이아웃 여백은 **같은 크기의 음수 마진**으로
되돌린다. (스크롤 컨테이너를 없앨 수는 없다 — 가로 스크롤이 이 행의 기능이다.)

```css
.shot-row {
  overflow-x: auto;
  padding: 1.5rem 1.25rem 4.5rem;    /* 24 / 20 / 72px — 그림자 50px + 여유 */
  margin: -0.75rem -1.25rem -3.75rem; /* 순 여백은 전과 같은 12px */
}
```

- 세로: `padding-top 24 + margin-top -12 = 12`, `padding-bottom 72 + margin-bottom -60 = 12`.
  **바뀐 건 클리핑 박스뿐이고 콘텐츠 위치·간격은 전과 동일하다.**
- 좌우: 스크롤 컨테이너의 `padding-left` 는 스크롤 원점에도 그대로 남으므로
  첫 스샷이 20px 밀린다 — 같은 크기 음수 마진이 이를 정확히 상쇄해 본문 글과
  왼쪽이 맞는다.
- **좌우 값은 섹션의 `px-6`(24px)보다 작아야 한다.** 크면 행 박스가 뷰포트를
  넘어 가로 스크롤이 생긴다. 20px 은 24px 안에 들어간다.

고친 뒤 실측: `215 → 250` 이 75px 에 걸쳐 매끄럽게 떨어지고, 프레임 좌측 바깥
(x=15px)에도 `240 → 250` 의 번짐이 생긴다.

## 왜 못 잡았나

`.shot-row` 의 `padding: 0.75rem 0` 은 **가로 스크롤 시 스샷이 잘리지 않게 하려는
여백**으로 들어간 값이라, 그림자 크기와 맞춰본 적이 없었다. 그림자는 스샷에
붙은 별개 규칙(`.screenshot`, 나중엔 `.shot-frame`)이어서 둘의 관계가 한눈에
보이지 않았다. 데스크톱 캡처에서는 지면이 흰색이고 프레임이 좁아 띠가 거의
안 보였고, **모바일 폭에서 지면이 `--color-bg-alt`(회색)인 섹션**에서만 도드라졌다.

## 재현 레시피

```bash
npm run dev -- --port 4399
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=2 \
  --window-size=500,3000 --virtual-time-budget=6000 \
  --screenshot=out.png http://localhost:4399/ko/apps/timetable
```

`data-device="ipad"` 로 기본 탭을 바꿔 캡처한 뒤, 프레임 아래 세로 한 줄의
픽셀 밝기를 찍어 **흐려지다 끊기는지** 본다. 눈으로만 보면 "그림자가 좀 세네"
정도로 지나친다 — 판정은 픽셀 수열이다.

## 교훈

- 그림자·아웃라인·툴팁처럼 **프레임 밖으로 나가는 표시**는 스크롤 컨테이너 안에
  두는 순간 잘린다. 한 축만 스크롤해도 양축이 잘린다.
- 스크롤 행에 패딩을 정할 땐 **자식의 그림자 반경을 계산해서** 정한다
  (`offset-y + blur/2` 아래, `blur/2` 옆). 어림치로 "여유 좀" 하면 딱 이 꼴이 난다.
- 스크롤 컨테이너의 패딩은 음수 마진과 짝으로 써야 레이아웃이 안 흔들린다.
